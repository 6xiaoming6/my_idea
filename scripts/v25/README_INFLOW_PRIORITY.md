# I28：I25 单变量流入验证

用户要求 I26 完成后优先跑 I25 的单变量流入版本。队列顺序为 **I26 → I28 → I27 → 原 I19–I22**；只暂挂未启动训练的 I27 等待控制器，I26 的训练、六套测试和报告继续自然完成。

## 具体做法与复现

- I28 的所有结构、训练和评估设置复制已冻结 I25 配置，仅将 `model.c_in` 改为1，并在独立 NPZ 中从 F/M/C 三个完整数组同时提取第0通道（流入）。通道映射来源为 `scripts/prepare_taxibj_npz.py`；完整保存来源哈希和数据清单。
- F/M/C 输入分别为 `[B,1,12,32,32]`、`[B,1,12,16,16]`、`[B,1,12,8,8]`。无流出观测、流出目标或流出聚合监督。样本顺序和划分不变；各尺度仍各自生成四族混合0.4掩码，沿用 I25 种子与逐epoch重采样规则。
- H0三尺度融合；前三轮自由尺度、末轮F；四轮共享八专家、原生Top2；±0.1 RMS匹配受控差分、因果预测历史、学习分配投影全部保留。
- 损失仍为 `(1−β)×投影后F缺失L1 + β×投影前同位置L1 + 0.1×投影前可见M/C聚合L1 + 0.01×候选均衡`。β为全局标量，初值0.3。所有重建和约束仅对流入计算。
- seed7、100epoch、batch32、每5epoch验证、AdamW、lr1e-3余弦至3e-4、AMP、梯度裁剪1；仅ID验证MAE选best，保存完整best/last。
- 从 **c_in=1 的独立随机初始化**训练，不加载双变量训练权重，不声明与旧双通道初始化逐张量一致。维度相关参数量变化如实披露。
- 独立入口 `scripts/v25/run_inflow_priority.py --prepare-only` 冻结计划、源码、配置和初始化。运行时用冻结目录内同名脚本 `--suite <suite>`。冻结后禁止修改对应源码与配置。
- CPU验证完成后，等待I26结束，在GPU1执行原尺寸batch32的AMP前后向、八次专家执行、可见约束和完整检查点恢复预检，然后训练与六套测试。不使用GPU0。每15秒记录run内`logs/gpu_status.jsonl`。
- 专用tmux以队列为主进程，完成报告后退出；成功后释放原I27等待器。失败留存日志并停止，不无限重试、不自动运行后续训练。原完成组跳过、中断组由完整last恢复。

## 比较边界

I28是单变量任务，旧I25汇总MAE包含流入和流出，二者不能直接比较或沿用I08双通道ID门槛8.8709。当前仅验证单变量配置的可行性和六套协议表现。若比较单、双变量训练，应对旧I25另做**仅流入评分**并使用一致掩码；本次不擅自新增该评估任务。单seed与测试掩码复测不能证明统计显著性。

报告由 `report_inflow_priority.py` 在 `experments_report/` 导出，按“具体做法与复现→完整结果、训练曲线和诊断→分析和边界”组织；不将旧双变量结果混入排名。
