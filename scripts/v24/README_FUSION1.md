# v24 第一方向：已选专家的条件化融合

入口：`scripts/v24/run_fusion1.py`。默认 TaxiBJ，可通过 `--dataset bikenyc` 切换；五组按下表串行运行，双卡 DDP 只服务当前一组，不会并行跑两组。默认 80 epoch、每 5 epoch 验证、seed 7、全局 batch 16、九类同分布混合 random@0.4，训练每轮重采样，验证/测试固定。每轮从共享八专家池激活 Top-2；不保存 `best.pt`，最优权重在内存中用于最终测试。

| 顺序 | 名称 | 唯一实验变量 | 要回答的问题 |
|---|---|---|---|
| 1 | `pair28_warm` | 28 对交互评分，第 1–3 epoch 的前两轮激活全部八专家；第 4–5 epoch 从稠密混合过渡；第 6 epoch 起恢复硬选一对 | 早期全专家训练能否改善此前 28 对组第 1、2、4 轮的组合集中？ |
| 2 | `top2_context` | 原生 Top-2 专家身份不变；融合修正只看当前路由状态、缺失支撑、专家身份与个体 logits | 状态感知融合能否优于原始两分数 softmax？ |
| 3 | `top2_response` | 与第 2 组同结构同参数量；额外输入两个已选专家的实际输出及差异 | 观察专家响应能否带来增益，而不仅是增加融合器容量？ |
| 4 | `top2_local` | 相同原生 Top-2，按时空位置从已选专家输出和观测支撑生成局部融合修正 | 局部缺失是否需要局部专家权重？ |
| 5 | `top2_proposal` | 仍只执行原生 Top-2；两位专家分别生成补全提议，读取提议差异、观测点残差与缺失区域变化，再按位置修正权重 | 实际补全提议是否比仅看隐藏特征的局部门控更能判断专家贡献？ |

四种新融合器的输出层零初始化，初始输出等于原生 Top-2 融合。后 4 组只运行被选中的两个专家；路由选择、原生候选重要性均衡项及训练损失保持同一协议，新增融合器只通过主任务损失学习。局部组增加一个小型空间卷积。提议组在此基础上额外读取两次共享解码器的只读提议，保留同样的 Top-2 选择和主损失；额外计算成本与门控输入维度会单独报告。提议探测只使用观测输入，不读取缺失位置的真值，也不通过探测分支反传到专家或解码器。

现有四轮共享原生 Top-2 的测试 MAE 为 21.389；历史 28 对组为 20.957；历史最优的残差搭档修正融合加头部排名监督为 19.932。这些是 seed 7 的参考值，旧结果每 2 epoch 验证，本轮每 5 epoch 验证。重点先比较本轮第 2–5 组的验证和测试排序、九类缺失 MAE、逐轮融合权重及实际前向时延。单个 seed 只用于筛选，不能作为稳定性或创新性的最终证明。

启动：

```bash
python -u scripts/v24/run_fusion1.py --gpus 0,1 --epochs 80
```

输出在 `outputs/v24-COE/experiments/coe_fusion1/`；完成作业经回执校验后跳过。`--dry-run` 可检查配置和队列，不启动训练。
