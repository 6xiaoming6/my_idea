# 四轮八专家：独立 MoE、共享原生 Top-2 与四种搭档路由

本组按顺序运行六组，统一 TaxiBJ（可切换 BikeNYC）、九类混合 random 0.4 mask、T=12、dim=64、四轮八专家 `T/S/TD/SD/TA/ST/TL/SL`、每轮真稀疏 Top-2、全局 batch 16、seed 7、默认 80 epoch 和相同余弦调度。六个模型都关闭显式补全反馈；第一组使用每轮独立专家池，其余五组跨轮共享专家池。六组都不保存 `best.pt`，由验证 MAE 选最优轮次后从内存中的权重测试。

| 顺序 | 组名 | 专家权重 | 搭档选择 |
| --- | --- | --- | --- |
| 1 | `residual4_moe` | 四轮独立池 | 原生个体 Top-2 |
| 2 | `residual4_partner_legacy` | 跨轮共享池 | 旧 P1：零初始化的纯搭档头分数 |
| 3 | `residual4_partner_residual` | 跨轮共享池 | `s_j=z_j+d_theta(phi_i,j)`，修正头零初始化，系数固定 1 |
| 4 | `residual4_shared_native` | 跨轮共享池 | 原生个体 Top-2，无搭档头与排名监督 |
| 5 | `residual4_partner_fusion` | 跨轮共享池 | 残差搭档评分选择；修正后的搭档分数也参与组内融合 |
| 6 | `residual4_partner_fusion_headonly` | 跨轮共享池 | 第 5 组基础上，候选排名损失只更新搭档评分头 |

第 2、3、5、6 组的主专家均来自个体 Router，主专家先执行并生成提议，再由共享搭档头选择第二位。四者采用相同候选试运行与排名监督：每卡每 16 batch 试运行 3 个候选，排名损失权重 0.1；第 2、3 组用原个体 logits 融合，第 5、6 组用主专家原分数与搭档修正分数融合。第 1、4 组都没有搭档头或额外排名训练；“1 对 4”只改变专家是否跨轮共享，“4 对 2/3”检验搭档选择加额外监督的整体效果，“2 对 3”直接检验纯评分与残差评分。六组按相同 epoch 和 batch 预算比较，并记录训练时长、参数量、实际前向次数；排名探针给第 2、3、5、6 组增加额外训练计算，不能将它们与第 1、4 组视为同计算量对照。

残差搭档（第 3、5、6 组）在初始化时与相同已有参数的原生 Top-2 保持四轮主专家、搭档、组内权重、最终输出一致；并列时采用 `torch.topk` 的同一回退顺序。但两者的软候选概率分布不同，`balance_importance=candidate` 的值和梯度不保证一致；第 3、5 组的排名损失还直接经过原生 Router 分数；第 6 组对用于排名的骨干特征和原生 logits 停止梯度。因此这里只声明**前向初始行为一致**，不声明完整训练目标等价。训练日志保留每轮与原生 Top-2 的组合分歧率、候选重要性熵、balance、修正项平均幅度与原生第二/第三名间隔，以及每 64 个全局 batch 在探针步上记录主任务与加权排名损失对解码器和被选为主专家的专家参数的梯度范数与余弦。共享专家可能在其他样本中同时充当搭档，因此后者是“被选为主专家的参数组”，不是纯主专家因果梯度。

```bash
python -u scripts/v24/run_coe_partner_residual4.py --dataset taxibj --gpus 0,1 --dry-run
tmux new-session -s v24-partner-residual4 \
  'python -u scripts/v24/run_coe_partner_residual4.py --dataset taxibj --gpus 0,1 --epochs 80'
```

单卡用 `--gpu 0`，双卡 DDP 用 `--gpus 0,1`，BikeNYC 用 `--dataset bikenyc`。单卡与双卡的每卡 balance 聚合范围不同，应分别看待。前三组已完成时，入口核对旧配置、回执、日志和封存的训练源码哈希后直接跳过，按第四、五、六组的顺序运行；既有三组所属的不可变实验套件不会改写。若该协议没有可复用的已完成套件，则按原顺序训练全部六组；不要同时启动其他 GPU 队列。主结果看验证 MAE、测试 MAE/RMSE、每轮选择分歧率与专家使用率，完成后 `six_arm_comparison_<fingerprint>.json` 汇总六组及相对第 4 组的测试 MAE/RMSE 差值。单 seed 只能筛选机制，若发现稳定收益再做多 seed 与计算预算匹配复核。

第 5 组检验搭档修正分数是否需要同时决定“选谁”和“给多少权重”；它与第 3 组的差别只有组内融合权重。第 6 组进一步检验候选排名监督的梯度是否干扰骨干；它与第 5 组只差排名损失的梯度通道。第 4 组在上次手动暂停时尚未完成，且未保存可恢复权重，因此本队列从第 4 组 epoch 1 重跑。
