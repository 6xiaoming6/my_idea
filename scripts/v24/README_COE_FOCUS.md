# 可切换数据集：CoE 与分层 MoE、组合路由的六组对照

本批实验只回答两个问题。第一，三轮 CoE 相比同深度分层 MoE 是否有性能或参数效率优势；第二，按学习到的专家对评分选两个专家，是否优于按六个个体路由分数选 Top-2。默认使用 TaxiBJ random 0.4；也可在启动时用 `--dataset bikenyc` 切换到 BikeNYC random 0.4。两种数据集均采用九类缺失模式均衡混合；训练 mask 每轮重采样，验证和测试使用各自固定的同分布 mask。模型种子 7、全局 batch 16、三轮、六类专家 T/S/TD/SD/TA/ST、hard Top-2、相同训练损失及路由辅助损失。默认 50 epoch、每 5 epoch 验证、按验证 MAE 选最优轮次，最佳权重仅保存在内存中直到测试完成。

| 顺序 | 组别 | 专家池 | 中间补全反馈 | 选两个专家的规则 | 直接用途 |
| --- | --- | --- | --- | --- | --- |
| 1 | `focus_moe` | 每层独立六专家 | 无 | 个体分数 Top-2 | 分层 MoE 对照 |
| 2 | `focus_coe_independent` | 每层独立六专家 | 有 | 个体分数 Top-2 | 对比第 1 组，隔离补全反馈 |
| 3 | `focus_coe_shared` | 三轮共享六专家 | 有 | 个体分数 Top-2 | 对比第 2 组，检验共享专家的参数效率；与第 1 组比较整体效果 |
| 4 | `focus_pair_additive` | 三轮共享六专家 | 有 | 两个个体分数相加 | 与第 3 组前向选择等价，控制组合路由的梯度代理变化 |
| 5 | `focus_pair_capacity` | 三轮共享六专家 | 有 | 两个个体分数相加，Router 隐层 64→68 | 控制额外 Router 参数量；与第 4 组比较容量增益 |
| 6 | `focus_pair_interaction` | 三轮共享六专家 | 有 | 相加分数 + 学习到的专家对交互分数 | 与第 4、5 组比较真正的组合选择收益和容量效应；与第 3 组比较完整增量 |

按当前配置实测，组 1/2 各 **447,543** 参数，组 3/4 各 **196,663** 参数；共享专家池减少约 **56.1%** 的整网参数。组 5 为 **199,363**，组 6 为 **199,588**，两者仅差 **225** 参数，因此可较好地控制 Router 容量因素。这些数字由当前代码实例化得到；若更改网络宽度应重新计算。

“分层 MoE”在这里是**同一编码器、共享点级分支和解码器之下的分层 MoE 式控制组**：隐藏状态逐层更新，每层有独立专家池和 Router，但后续层只读取初始补全，不读取前一轮解码的补全或补全变化。它不是对所有 MoE 架构的普遍比较。第 1、2 组参数结构完全相同；第 2、3 组主要差别是专家参数跨轮是否共享，所以第 3 组参数更少。应同时报告测试 MAE/RMSE、每缺失族误差、总参数量、训练/推理耗时与显存。无反馈控制组为隔离机制保留了逐轮解码计算，因此该组耗时不是高度优化的通用 MoE 实现速度。

“最佳组合”指**模型根据当前观测学习预测得分最高的专家对**。推理时没有真实缺失值，因此不能用真值逐对试验后选 oracle。交互头会给六专家组成的 15 对额外评分；训练日志中的 `coe_step*_pair_vs_top2_disagreement_rate` 衡量它有多少次真正偏离个体 Top-2。若该值始终近零，第 6 组并未充分检验不同选对；若非零但误差更高，组合评分目前没有带来收益。第 4 组控制了确定性选择代理梯度的改变，第 5 组控制了近似相同的 Router 参数量，避免把这项变化误认为组合交互收益。

hard Top-2 的模型前向按样本把输入派发给入选的两个专家，仅计算这两个专家的输出并归一化融合；不会先对每个样本跑完六个专家。不同样本可能选不同的对，因此一个 batch 可能触及六个专家，但每个专家只处理选中自己的样本。Soft/Parallel 模式按定义仍用全池融合，本批不包含它们。

检查计划：

```bash
python -u scripts/v24/run_coe_focus.py --dataset taxibj --gpus 0,1 --dry-run
```

本地顺序启动，每次只训练一组双卡 DDP 模型：

```bash
tmux new-session -s v24-coe-focus \
  'python -u scripts/v24/run_coe_focus.py --dataset taxibj --gpus 0,1 --epochs 50'
```

切换到 BikeNYC 只需把命令中的 `--dataset taxibj` 改为 `--dataset bikenyc`；也可通过 `--config <实验策略 JSON> --study <研究名>` 指定其他数据配置。数据文件、网格尺寸和输出根目录由所选策略及其 base config 决定，不需要改代码。完整组会按回执自动跳过，中断组从头重跑。单种子用于筛选；若差异较小，应对第 1、2、3、6 组追加配对种子，再评估稳定性。运行结果分别位于 `outputs/v24-COE/TaxiBJ/` 或 `outputs/v24-COE/BikeNYC/`；队列摘要位于所选策略的 `output_dir/<study>/<fingerprint>/summary.csv` 与 `comparison.json`。历史 BikeNYC 七组策略配置为 `configs/v24/team_accept_v4_bikenyc_experiments.json`，不属于当前六组队列。
