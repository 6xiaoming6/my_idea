# 20260928_v24_五组共享反馈与搭档路由结果分析

## 1. 实验目的与实际设置

这轮五组对照检验两个问题：跨轮共享专家池是否比每轮独立专家池有实用的参数—误差取舍；利用主专家实际提议选择搭档，是否优于原生个体 Top-2。M0/M1/C0/C1 是“每轮独立/跨轮共享 × 无/有显式补全反馈”的 2×2 矩阵，P1 在 C1 上改用主专家条件化搭档路由。组别依次为 M0=`focus_moe`，M1=`focus_coe_independent`，C0=`focus_shared_no_feedback`，C1=`focus_coe_shared`，P1=`focus_partner`。

**以实际生成配置和回执为准，本批是 70 epoch，不是先前讨论的 80 epoch。**五组均为 TaxiBJ、random 0.4 九类混合 mask，训练 mask 每轮重采样，验证/测试为固定且可复现的九类混合 mask；seed 7，单张 RTX 3090，全局 batch 16，每轮 154 个训练 batch，每 2 epoch 验证一次，共 35 次验证。每组均训练 70 轮，没有提前停止；AdamW、主学习率 0.001、cosine70、AMP、三轮链、六专家、每轮 Top-2、隐藏维度与 Router 隐藏维度均 64，接受门关闭。按验证 MAE 选择并保存最佳权重，再只测试一次。新的共同路由均衡系数为 0.01，importance 使用各组实际候选对概率与组内权重的六维边缘分布；单卡 batch 16 上聚合。P1 额外使用候选排名损失，权重 0.1。

训练、验证、测试数据量分别为 2452、342、707 个 `[2,12,32,32]` 样本。此轮只有一个种子；下文差异均为单次运行的描述，不能解释为统计显著性。当前结果也不应与旧 BikeNYC focus 直接合并，因为数据集及共同 loss 口径不同。

## 2. 最新代码中的模型与评价流程

输入 `x_f_obs` 和二值观测 mask `m_f` 的形状为 `[B,2,12,32,32]`；原始观测在链中保持固定，临时补全值不会被当作真实观测。模型采用 fine 单尺度：输入编码、观测支撑和位置特征进入统一隐藏状态，三个独立 Router 在每轮根据当前状态给六专家 T/S/TD/SD/TA/ST 打分。每轮还有共享点级更新分支；选中的两个模式专家只处理被分配的样本窗口，读取同一轮的统一输入，按原 Router 个体 logits 的组内 softmax 归一化融合。每轮更新隐藏状态并解码；有反馈组会把当前补全值及其变化供下一轮读取，无反馈组仍保留计算可比的逐轮解码，但下一轮不读显式补全反馈。`per_step` 为每轮独立的专家实例，`shared` 为三轮复用同一专家池；Router 在各组都逐轮独立。

P1 先由原 Router 选主专家并执行，用该输出做一次临时解码；共享搭档评分头读取可见状态、主专家身份、输出及相对旧估计的变化，从剩余五位选一位。第二位专家仍读取本轮原输入，而不是主专家更新后的输入。正常推理每轮只执行主专家与一位搭档，但增加临时解码和先主后辅的调度。每 16 个训练 batch，在一个轮次上最多试运行三个搭档并重跑后续链；训练隐藏标签仅构造无梯度的候选误差排名，不进入评分头输入。P1 共记录 2100 次额外完整前向调用。

监督只作用于原 mask 隐藏且有有限真值的位置。公共训练损失为最终补全 L1 加 0.01 倍每轮平均的候选策略匹配 balance；中间监督和 z-loss 系数均为 0。P1 在探测 batch 额外加入 0.1 倍候选排名交叉熵。最终 MAE/RMSE 从隐藏目标的误差分子、平方误差分子与有效目标数精确汇总。测试 MAPE 高达 20 万至 31 万，受零值或近零值目标影响明显，不用于本轮排名；WAPE可作为辅助，结论以 MAE/RMSE 为主。

最佳 checkpoint 包含模型、优化器、调度器、AMP scaler 和各 rank RNG 状态。末轮 Oracle 在最佳权重的前 48 个固定验证样本上，保持前两轮自然路径，分别穷举末轮 15 对并重跑最终预测；`J_top2`、`J_anchor_best`、`J_all_best` 均使用验证标签计算，只用于诊断，不能作为可部署模型成绩或测试集选型依据。

## 4. 配对结果：能证明什么

- **反馈在本设置下没有带来收益。**固定独立池，M1 比 M0 测试 MAE 高 2.011（+9.12%）；固定共享池，C1 比 C0 高 1.478（+6.55%）。两个方向一致，说明本批显式补全反馈值得重新审视，但一个种子及 70 轮不能证明反馈机制普遍无效。
- **共享池主要换来参数压缩，不是当前的精度胜利。**无反馈时 C0 相比 M0 参数减少 56.06%，测试 MAE 仅高 0.515（+2.34%），纯前向约快 4.5%；这是本批最有价值的紧凑模型取舍。有反馈时 C1 与 M1 的测试 MAE 分别为 24.039、24.056，仅差 0.018，不足以声称共享提高精度，但参数仍减少 56.06%。
- **P1 当前整体失败。**它比 C1 测试 MAE 高 2.756（+11.47%），RMSE 高 6.672；参数多 12.93%，整次训练慢 17.9%，测试纯前向慢 14.0%，峰值显存多约 0.35 GB。P1 也比 M0 的测试 MAE 高 4.749（+21.54%），不能作为本批主模型候选。
- **验证与测试排序一致。**两者均为 M0、C0、C1、M1、P1；C1/M1 的差距很小。C1 的最佳验证轮次恰是第 70 轮，继续训练可能改变局部排序；其余组最佳在 52 或 68 轮。所有组测试 MAE 低于最佳验证 MAE，说明两划分难度不同，不能把这点当成泛化提升。

九类固定测试 mask 的分组 MAE 进一步显示 P1 的退化主要发生在结构化缺失：

## 5. 路由与 Oracle：新选择有用，但当前模型仍差

| 最佳 checkpoint 的前 48 个固定验证样本 | `J_top2` | `J_anchor_best` | `J_all_best` |
| --- | ---: | ---: | ---: |
| M0 | 22.890 | 22.481 | 21.924 |
| M1 | 23.679 | 22.872 | 22.765 |
| C0 | 23.230 | 22.364 | 22.121 |
| C1 | 23.819 | 22.983 | 22.888 |
| P1 | 32.934 | 25.936 | 25.496 |

`J_all_best ≤ J_anchor_best ≤ J_top2` 是候选集合包含关系造成的数学事实，Oracle 比 Top-2 低本身不是模型成果。P1 的原生末轮 Top-2 特别差；按当前代码和最佳权重在**同一 48 个验证样本**复算，P1 实际自然路径 MAE 为 **26.527**。仅将第 1、2、3 轮分别替换为该 P1 权重自身的原生 Top-2，并重新执行后续链，最终 MAE 分别为 **29.826、26.701、32.934**。因此新搭档选择在 P1 自身内部确有作用，尤其第 1 和第 3 轮；“P1 比 C1 差”不能直接解释成评分头完全没有学到有效选择。

不过 P1 的末轮全 15 对 Oracle 仍为 25.496，而 C1 在这批相同验证样本上的自然 Top-2 为 23.819。即使末轮用真值选最优专家对，P1 也追不上 C1。这说明当前差距不可能仅靠修正**末轮**搭档决策消除；更可能涉及前缀状态、主专家选择、专家训练分布或三轮联合优化。此判断只针对两个各自最佳 checkpoint 的 48 样本验证子集，不是对所有数据或任意重训练的上界证明。P1 自然路径距自身含主专家最优 0.591、距全部对最优 1.031，仍有选择改进余地，但明显小于它相对 C1 的模型差距。

P1 在测试集与原生 Top-2 的专家对不一致率第 1/2/3 轮为 60.6%/58.8%/87.6%；组合路径熵 2.597，高于 C1 的 0.819，说明更丰富的路径并未自动带来更低误差。另一方面，P1 第 2 轮 ST 获得约 93.3% 的融合权重，仍存在局部专家集中，不能以整体路径数多就认定没有坍缩。P1 候选排名损失从约 1.099 降至 1.020，评分头梯度非零；但这是软目标交叉熵，不能直接换算成准确率。零初始化评分头在初期给非主专家近似同分，`argmax` 会受索引顺序影响；训练第 1 轮的三层专家对相对原生 Top-2 不一致率已达约 84%/81%/84%。这可能让 P1 从一开始就在明显不同的专家训练分布上优化，是下一轮需要控制的实现假设，而不是由本轮结果单独证明的因果原因。

## 6. 训练趋势与异常

- M0：验证 MAE 从 epoch 2 的 60.983 降至 epoch 30 的 27.947、epoch 50 的 24.555，于 68 达 23.286；70 时为 23.297，已接近平台。最终测试 MAE 22.045、RMSE 37.936，为五组最佳。
- M1：验证 MAE 在 epoch 2/30/50 分别为 61.120/27.506/25.367，52 达最佳 25.193；之后到 70 约 25.283，改善停滞。比 M0 多的反馈未产生精度收益。
- C0：验证 MAE 在 epoch 2/30/50 分别为 62.916/28.958/24.893，68 达 24.105，70 维持 24.121；测试 22.560。它以约 44% 的 M0 参数量保持相近但仍较差的误差。
- C1：验证 MAE 在 epoch 2/30/50/70 为 62.091/29.326/26.006/24.825，最佳落在最后一轮，没有明确验证集反弹证据。当前不足以把反馈劣势解释为过拟合；也可能有收敛速度差异。
- P1：验证 MAE 在 epoch 2/30/50/68/70 为 65.065/35.630/29.333/27.960/27.967，训练 MAE 在 68 为 29.098。该组并未发散，但整体收敛慢、最终平台更高，结构化缺失退化明显。

五组未发现 NaN/Inf、缺失 epoch 或缺失测试记录；也没有可用于多 seed 方差估计的重复运行。最佳 epoch 靠近预算末端的 M0/C0/C1/P1 值得在确认新方法可行时延长训练，而不应直接凭当前 70 轮判断最终极限。

## 8. 结论与下一步

现阶段准确率主模型应保留 **M0**；如果论文要强调参数效率，可把 **C0** 作为较紧凑的候选，同时诚实报告其测试 MAE +2.34% 与参数 −56.06% 的取舍。此批不支持“多轮共享 CoE 精度优于分层独立 MoE”，也不支持“新搭档策略 P1 整体优于原生 Top-2”。反馈在两种专家池设置下都变差，是优先核查的机制。

P1 的值得保留的发现是：条件化搭档在自身 checkpoint 中优于自身原生 Top-2，但较差的前缀/表示让末轮 Oracle 也追不上 C1。下一步先做小规模、严格配对的 **C1→P1 稳定初始化** 对照：让新评分在初期退化为原生第二名，再逐步放开学习修正，保持主专家、公共损失和预算一致；同时记录逐轮的主专家、搭档、候选误差与更新幅度，特别检查结构化缺失。若仍无跨模型收益，就停止扩展组合路由，转而检查反馈设计与共享池容量。最终关键比较至少三 seed，再用 BikeNYC 的同一冻结协议复核；不要用验证 Oracle 或测试族指标反复调参选型。
