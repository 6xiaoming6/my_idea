# V14 与 V18 三数据集全量实验对比分析

> 报告日期：2026-07-25  
> 对比版本：V14-single 与 V18-single  
> 数据集：TaxiBJ、BikeNYC、CHAP_Beijing  
> 实验范围：fixed/random，缺失率 0.2/0.4/0.6/0.8，共 24 个配对实验  
> 主指标：缺失位置、原始数据尺度上的全局 MAE 和全局 RMSE

## 1. 对比结论摘要

本次对比没有直接照搬 V14 旧报告中的测试指标，而是重新加载 V14 的全部 24 个 `best.pt`，在当前统一的“全测试集缺失元素累计”指标口径下重新评测，再与 V18 正式结果比较。

核心结论如下：

1. **V18 并没有全面超过 V14。**在 24 个配对点中，V18 的 MAE 和 RMSE 都是 **10 胜、14 负**。
2. 按每个实验点的相对变化平均，V18 的 MAE 比 V14 **高 1.96%**，RMSE **高 2.80%**；相对变化中位数分别为 **+0.66%** 和 **+0.41%**。
3. **TaxiBJ 整体基本持平但分化严重**：V18 八点平均 MAE 退化 1.00%，RMSE 退化 2.77%。其中 random 平均显著改善，但 fixed 明显退化。
4. **BikeNYC 明确是 V18 的弱项**：八点平均 MAE 退化 4.48%，RMSE 退化 4.91%；8 个点只在 fixed@0.8 取得极小优势。
5. **CHAP_Beijing 是 V18 唯一整体优于 V14 的数据集**：八点平均 MAE 改善 0.84%，RMSE 改善 1.06%，其中 fixed@0.4 和 random@0.4 的优势最明显。
6. V18 的结构安全性和可解释性明显强于 V14：残差有严格尺度界限，24 点的硬边界违反率均为 0；V14 虽然性能更强，但其原始 C2F 候选误差非常大，依赖“小 gate × 大 correction”的尺度补偿，安全含义不够严格。
7. **如果只根据当前 MAE/RMSE 选择论文主模型，V14 仍然更稳妥。**它在更多实验点获胜，并且在 TaxiBJ、BikeNYC 上保留更好的最佳结果。
8. **如果目标是继续研究有界、安全、可解释的残差校准，V18 的结构方向更合理**，但在成为最终主模型前必须解决 BikeNYC 和 TaxiBJ fixed@0.2/0.4 的明显退化。

因此，当前不能写成“V18 全面优于 V14”。更准确的结论是：

> V18 用更严格的有界残差机制换取了更好的结构安全性，并在 CHAP_Beijing 和 TaxiBJ 中高缺失 random 场景中取得收益；但其跨数据集性能尚未达到 V14 的总体水平。

## 2. 对比口径与公平性检查

### 2.1 实验覆盖

两个版本均完整覆盖：

```text
3 datasets × 2 mask patterns × 4 missing rates = 24 runs
```

两版的 24 组正式实验均具备：

- 完整训练日志；
- 定期验证日志；
- 单一验证最优模型 `best.pt`；
- 训练结束后重新加载最优模型；
- 完整测试记录；
- 有限的 MAE、RMSE、MAPE；
- 正常结束状态。

### 2.2 共同设置

两版使用相同的：

- 数据集划分路径；
- fixed/random 掩码路径；
- 数据 shape；
- batch size；
- 随机种子 42；
- AdamW；
- 主干学习率 `1e-3`；
- weight decay `1e-4`；
- cosine scheduler；
- `eta_min=1e-6`；
- AMP；
- 梯度裁剪 1.0；
- 以验证 MAE 选择唯一最优 checkpoint；
- 训练结束后只运行一次测试集。

数据规模一致：

| 数据集 | Train / Val / Test | 输入 shape | Batch size |
|---|---:|---:|---:|
| TaxiBJ | 2491 / 356 / 712 | `[N,2,12,32,32]` | 32 |
| BikeNYC | 511 / 73 / 147 | `[N,2,12,24,12]` | 16 |
| CHAP_Beijing | 2626 / 322 / 322 | `[N,1,7,32,32]` | 32 |

### 2.3 原始指标口径不一致

V14 训练时的指标逻辑为：

```text
先计算每个 batch 的 MAE/RMSE
再对所有 batch 指标做等权平均
```

V18 已改为：

```text
累加全数据集所有缺失位置的绝对误差、平方误差和元素数量
最后统一计算全局 MAE/RMSE
```

旧方法会使最后一个较小 batch 与完整 batch 权重相同；RMSE 还会受到“先开根号再平均”的额外偏差。因此 V14 原报告数值不能直接与 V18 进行论文级比较。

本报告重新加载了 V14 的 24 个最优 checkpoint，并同时重算旧口径和全局口径。重算的旧口径与历史日志最大绝对差约 `1.3e-3`，证明 checkpoint、数据和模型读取均正确。

典型差异如下：

| 实验 | V14 旧日志 MAE | V14 全局 MAE | V14 旧日志 RMSE | V14 全局 RMSE |
|---|---:|---:|---:|---:|
| TaxiBJ fixed@0.2 | 8.7773 | 8.6429 | 15.1266 | 15.7068 |
| BikeNYC fixed@0.2 | 2.5408 | 2.5711 | 6.0984 | 6.2490 |
| CHAP fixed@0.4 | 0.5886 | 0.5898 | 0.8518 | 0.9130 |

后文的所有 V14 测试指标都采用重新计算的全局口径。

### 2.4 仍然存在的公平性限制

重新评测统一了测试指标，但不能消除以下差异：

1. V14 的 checkpoint 是按旧 batch-average 验证 MAE选出的；
2. V18 的 checkpoint 是按全局验证 MAE选出的；
3. V14 所有实验跑满配置 epoch，V18 的 BikeNYC random 使用 early stopping；
4. 两版都只运行了 seed=42；
5. 两版实验运行时都记录为 `git_dirty=True`；
6. V18 记录了数据、掩码和源码 SHA256，V14 没有同等级指纹。

因此，本报告比直接比较旧日志严格得多，但仍不能替代“同一代码口径、同一 early-stop 设置、clean tree、三随机种子”的最终重跑。

## 3. 模型结构对比

### 3.1 共同主干

V14 和 V18 都复用相同类型的 `MultiScaleMoEBackbone`：

1. fine/mid/coarse masked pooling；
2. 三尺度 token encoder；
3. 四个共享专家；
4. Top-2 稀疏路由；
5. shared branch 与 routed branch；
6. coarse→mid→fine 多尺度融合；
7. 尺度门控和可靠性门控；
8. 主预测头输出 `x_base`。

两版都不复制第二套主干和专家池，差异主要位于 `x_base` 之后的校准结构，以及校准损失对主干联合训练产生的影响。

### 3.2 V14：绝对值 C2F 候选与安全门控

V14 首先生成完整的绝对值 C2F 候选：

```text
x_coarse = CoarseHead(z_c)
x_mid = up(x_coarse) + alpha_mid × delta_mid
x_ctf = up(x_mid) + alpha_fine × delta_fine
```

随后 CorrectionAdapter 输入：

```text
[x_ctf-x_base, x_base, x_ctf]
```

并输出 `delta_ctf`。最终结果为：

```text
x_final = x_base + alpha_final × delta_ctf
```

控制器使用难度、可靠性、scale gate、几何特征和观测一致性统计，预测：

- `alpha_mid ≤ 0.8`；
- `alpha_fine ≤ 0.8`；
- `alpha_final ≤ 0.5`。

V14 的主要问题是：`alpha_final` 有界，但 `delta_ctf` 没有幅值约束。因此很小的 gate 可以与很大的 correction 相互补偿，gate 不能被严格解释为安全概率或真实修正比例。

### 3.3 V18：基线锚定有界残差金字塔

V18 不再生成一个可以远离主干的绝对值候选，而是在各尺度建立 detached 基线锚点：

```text
anchor_f = stopgrad(x_base)
anchor_m = resize(anchor_f)
anchor_c = resize(anchor_f)
```

各尺度只预测经过 `tanh` 限制的残差方向：

```text
d_c, d_m, d_f ∈ [-1,1]
```

观测位置计算通道 RMS 尺度 `s`，控制器输出有界预算 `rho`：

```text
rho_c ≤ 0.15
rho_m ≤ 0.15
rho_f ≤ 0.20
```

最终输出：

```text
x_final = x_base + rho_f × s_f × d_f
```

所以具有严格界限：

```text
|x_final-x_base| ≤ 0.20 × s_f
```

V18 还构建小步 probe：

```text
x_probe = stopgrad(x_base) + 0.05 × s_f × stopgrad(d_f)
```

并仅在观测位置计算相对误差、相对收益和相对变化幅度，使控制器输入对不同数据集的数值尺度更稳定。

### 3.4 结构差异总结

| 比较项 | V14 | V18 |
|---|---|---|
| 多尺度输出形式 | 绝对 coarse→mid→fine 候选 | 基线锚定残差方向 |
| 基线锚点 | 最终阶段参考 `x_base` | fine/mid/coarse 全部锚定 `x_base` |
| 修正幅度 | correction 本身无界 | `rho × observed RMS × tanh(direction)` |
| 最终上界 | 只有 gate 上界，无严格残差上界 | 严格 `0.20 × observed scale` |
| 控制信号 | 绝对观测误差与变化 | 相对观测误差、probe 相对收益 |
| 跨尺度传播 | 绝对候选逐层传播 | 可靠性过滤的残差方向传播 |
| 初始回退 | 零初始化 correction | 零初始化 direction |
| 安全可解释性 | 较弱，存在尺度补偿 | 较强，边界可验证 |
| 修正能力 | 强，但可能依赖大幅 correction | 保守，可能限制有效容量 |

### 3.5 损失差异

两版共同保留：

- 缺失位置 Smooth L1 主损失；
- 跨尺度一致性；
- MoE balance；
- shared/route auxiliary；
- complementary loss；
- 基线、多尺度和 regret 类辅助监督。

V14 特有部分：

```text
0.25 L_base
+ 0.05 L_mid
+ 0.03 L_coarse
+ 0.10 L_regret
+ 0.0001 L_gate
```

V18 对应为：

```text
0.25 L_base
+ 0.05 L_mid
+ 0.03 L_coarse
+ 0.10 L_sample_regret
+ 0.02 L_observed_guard
+ 0.0001 L_budget
```

V18 把 regret 提升为样本级比较，并新增 observed guard；这增强了安全约束，但也会改变主干与残差分支的联合优化平衡。

## 6. 分数据集详细分析

### 6.1 TaxiBJ：random 明显进步，fixed 低缺失率严重退化

TaxiBJ 是两版差异最不均衡的数据集。

#### fixed

V18 在 fixed@0.2 和 fixed@0.4 分别退化：

- MAE：+27.43%、+30.16%；
- RMSE：+39.06%、+41.53%。

这不是指标口径造成的小偏差，而是明确的大幅退化。fixed@0.6 基本持平，fixed@0.8 则小幅改善。

进一步拆分 V18 自身的主干和最终输出：

| 设置 | V18 `x_base` MAE | V18 最终 MAE | V18内部收益 | V14 最终 MAE |
|---|---:|---:|---:|---:|
| fixed@0.2 | 11.9274 | 11.0137 | 7.66% | **8.6429** |
| fixed@0.4 | 10.1167 | 9.9528 | 1.62% | **7.6468** |
| fixed@0.6 | 8.0393 | 7.7382 | 3.75% | **7.6982** |
| fixed@0.8 | 8.5168 | 7.9857 | 6.24% | 8.1476 |

V18 的残差分支在四组 fixed 中都改善了自己的 `x_base`。因此 fixed@0.2/0.4 的主要问题不是“最终残差方向完全错误”，而是 V18 联合训练得到的基线本身已经明显弱于 V14。

可能原因包括：

1. V18 的 base、多尺度方向、sample regret、observed guard 和 budget 同时优化，改变了主干的最优点；
2. V18 的硬残差上界无法像 V14 的无界 CorrectionAdapter 一样弥补较差主干；
3. fixed@0.2/0.4 的空间结构可能需要更大或更非局部的校正；
4. 控制器在这些组接近预算上界，说明模型已尝试扩大修正，但仍无法补回主干差距。

#### random

V18 在 random@0.4/0.6/0.8 分别改善：

- MAE：21.35%、5.86%、10.93%；
- RMSE：25.78%、7.57%、12.70%。

random@0.4 是 V18 相对 V14 最强的单点。这里 V18 的 `x_base` MAE 已经从 V14 最终的 10.8298 降到 9.0066，残差又进一步降到 8.5171。该收益主要来自更好的联合主干，其次才是最终有界残差。

V14 的 TaxiBJ random 最优轮次为 75、55、105、105，明显早于训练结束；V18 对应为 150、130、110、160。V14 的无界修正路径在 random 模式下更容易在中后期过拟合，而 V18 的有界约束延长了有效训练区间。

#### TaxiBJ 结论

V18 改善了随机缺失下的中高缺失率鲁棒性，但牺牲了固定低缺失率。若论文重点是 random@0.4–0.8，V18 有明显价值；若要求 fixed/random 全覆盖，V14 更均衡。

### 6.2 BikeNYC：V18 的预算接纳没有转化为有效修正

BikeNYC 是 V18 相对 V14 最明确的整体退化：

- fixed 平均 MAE 退化 4.22%；
- random 平均 MAE 退化 4.73%；
- 8 点只有 fixed@0.8 获胜；
- 该 MAE 优势仅 0.05%，不具备单种子统计说服力。

V14 在 BikeNYC 的内部基线到最终输出平均收益为：

- fixed：约 4.47%；
- random：约 7.30%。

V18 对应只有：

- fixed：约 0.28%；
- random：约 0.58%。

V18 的 fine 预算在多数 BikeNYC 实验中接近 0.20 上界，但最终收益仍很小；fixed@0.6、fixed@0.8、random@0.6 甚至比 V18 自身 `x_base` 略差。

这表明问题不是控制器过于保守，而是：

1. 残差方向质量不足；
2. observed utility 对零值占比较高的数据校准不够；
3. 控制器接近饱和，无法区分“预算不足”和“方向无效”；
4. V18 的尺度归一化可能无法表达 BikeNYC 中零值、低流量和热点区域的异质性；
5. V14 的无界 correction 虽然可解释性差，却确实提供了更强的拟合能力。

BikeNYC fixed 不同缺失率的被掩码目标尺度差异很大，fixed@0.6 的零值比例最高。V18 当前以通道 RMS 统一标定预算，可能被少量热点放大，而不能针对零值密集区域提供适当尺度。

#### BikeNYC 结论

当前 V18 不能替代 V14 作为 BikeNYC 主结果。下一版需要优先改进残差方向和零值感知控制器，而不是继续增大 `rho_max`。

### 6.3 CHAP_Beijing：V18 的设计假设最成立

CHAP_Beijing 是 V18 唯一整体改善的数据集：

- fixed 平均 MAE 改善 0.60%；
- random 平均 MAE 改善 1.07%；
- 5/8 点获胜；
- fixed@0.4、random@0.4 分别改善 3.44% 和 3.63%。

V18 在 CHAP 上表现出理想的“保守但有效”特征：

- 8 点最终预测全部优于自己的 `x_base`；
- 内部平均收益约 16%；
- 样本退化比例仅约 0.8%–1.9%；
- `rho_f` 平均仅约 0.026–0.038；
- 残差远未触及硬上界。

CHAP 的目标尺度稳定，几乎没有零值。相对观测效用和通道 RMS 尺度在这里具有清晰、稳定的统计意义，因此控制器不需要饱和就能获得高质量修正。

但是需要注意：V18 所谓“内部提升 16%”是相对同次训练的 `x_base`，不是相对 V14。与 V14 的最终输出相比，实际八点平均净收益只有约 0.84%。

#### CHAP 结论

V18 在 CHAP 上证明了有界残差设计可以同时实现安全性和性能，但总体提升仍较小，需要多种子实验确认。

## 7. 两版内部修正机制比较

### 7.1 V14 的优势与风险

重新评测 V14 后，24 点的最终输出都优于自己的 `x_base`。其平均内部收益较强，尤其是：

- TaxiBJ random：约 17.33%；
- BikeNYC random：约 7.30%；
- CHAP random：约 11.44%。

但 V14 原始 `x_ctf` 候选非常差。例如：

- TaxiBJ fixed@0.2：`x_ctf MAE=77.94`；
- TaxiBJ random@0.2：`x_ctf MAE=86.64`；
- CHAP fixed@0.4：`x_ctf MAE=22.21`；
- BikeNYC fixed@0.2：`x_ctf MAE=17.05`。

最终结果仍然变好，是因为 CorrectionAdapter 学会从巨大候选差异中提取有效 correction，再由很小的 `alpha_final` 缩放。这种机制拟合能力强，但无法从 gate 数值直接判断实际残差有多大。

### 7.2 V18 的优势与不足

V18 的全部残差都有明确尺度边界，24 点硬越界率为 0。它消除了 V14 的尺度不可辨识性，也避免了原始 C2F 候选远离基线的问题。

但有界性带来两个新问题：

1. 当联合训练得到的 `x_base` 较差时，有限预算无法完成足够修正；
2. 控制器即使给出接近最大预算，也不能保证残差方向正确。

因此，V18 解决的是“修正是否可控”，尚未完全解决“修正是否有效”。

### 7.3 不能把 V18 内部基线当成 V14

V18 的 `x_base` 只是 V18 训练中的主干输出，不等于独立训练完成的 V14：

- 两者外部分支不同；
- 辅助损失不同；
- 梯度流不同；
- optimizer 参数组不同；
- checkpoint 选择口径不同。

所以“V18 final 比 V18 base 好 16%”不能写成“V18 比 V14 好 16%”。正式版本差异必须以本报告的配对测试结果为准。

- sample regret 和 observed guard 使优化更保守；
- V18 的验证指标改成了全局口径；
- CHAP 多数组合在最后一轮仍改善。

V18 有 11/24 个最佳 checkpoint 位于最后一次验证，V14 约为 6/24。特别是 CHAP，V18 的 8 点中有 7 点最优轮次为 150，说明当前训练预算可能仍未充分覆盖其收敛平台。

## 9. 应该选择哪个版本

### 9.1 如果目标是当前论文主结果

建议优先选择 **V14**：

- 24 点赢 14 点；
- TaxiBJ 最佳 MAE/RMSE 更好；
- BikeNYC 八点整体明显更好；
- 跨数据集结果更均衡；
- V18 的部分提升尚未经过多种子验证。

但论文中不应把 V14 的 gate 描述成严格安全概率，只能描述为学习到的残差融合系数。

### 9.2 如果目标是下一阶段结构研究

V18 可以作为“安全残差方向”的研究基础，因为它具有 V14 不具备的：

- 严格残差上界；
- 尺度明确的预算变量；
- 相对观测效用；
- 基线锚定；
- 可验证的零越界率。

不过，不建议直接沿用当前 V18 配置继续叠加更多模块。下一版应首先恢复 V14 的有效修正能力。

### 9.3 推荐的折中方向

下一版本建议保留 V18 的安全框架，同时针对当前退化做最小修改：

1. **主干与 refiner 分阶段训练**：先得到稳定 `x_base`，再训练有界残差，避免辅助约束拉坏主干。
2. **从统一 RMS 改为更稳健的尺度估计**：对 BikeNYC 考虑非零值 RMS、分位数尺度或热点/零值双尺度。
3. **加入显式拒绝门**：同时预测“是否接纳”和“接纳幅度”，而不是只预测连续预算。
4. **改进方向学习**：先提高 direction 与真实缺失误差的方向一致性，再调节 `rho_max`。
5. **自适应上界而非简单放大上界**：TaxiBJ fixed 需要更强修正，但 BikeNYC 已经饱和；全局增大 `rho_max` 会放大错误方向。
6. **保留 V14 作为 teacher 或 warm start**：用 V14 的有效 correction 教 V18 学习有界方向，但测试时仍使用 V18 的硬边界。

## 10. 最终判断

从当前单种子全量结果出发：

| 评价维度 | 更优版本 | 判断 |
|---|---|---|
| 24 点获胜数量 | V14 | 14 比 10 |
| TaxiBJ 综合表现 | V14 略优 | V18 random 强，fixed 低缺失率退化大 |
| BikeNYC | V14 | V18 八点仅一处极小胜出 |
| CHAP_Beijing | V18 | 平均 MAE/RMSE 小幅改善 |
| 最佳单点结果覆盖 | V14 | TaxiBJ、BikeNYC 更好 |
| 结构安全性 | V18 | 严格有界、零越界 |
| 参数量 | V18 | 少约 1.6% |
| 训练成本 | 接近 | V18 略慢、略高显存 |
| 当前论文主模型 | V14 | 性能更均衡 |
| 安全残差研究基础 | V18 | 结构更清晰，但需继续修复 |

最终结论：

> V18 是一次成功的结构安全化尝试，但不是一次成功的全面性能升级。当前应保留 V14 作为性能主基线，同时以 V18 的基线锚定、有界方向和相对效用作为下一阶段改造部件。只有在统一协议、多种子重跑后，且修复 BikeNYC 与 TaxiBJ fixed 的退化，V18 或其后继版本才适合正式取代 V14。
