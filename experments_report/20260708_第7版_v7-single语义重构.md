# ST-MoE Imputer v7-single — 实验报告（第7版）

> 日期：2026-07-08 | 分支：v7-single | 实验：Full Model (fixed + random) × 3 数据集 | 种子：42
> 训练：150–160 epochs, Cosine LR(1e-3→1e-6), AdamW, SmoothL1 Loss, AMP

---

## 1. v7-single 改动说明

v7-single 在 main 分支基础上做了**语义层面的模块重新划分**，不改变模型的计算结构和训练流程：

| 改动 | 旧名称 (v6/main) | 新名称 (v7-single) |
|------|-----------------|-------------------|
| 共享专家 | `GatedCrossScaleSharedExpert` → `cross_scale_shared_expert` | 抽象为 `GlobalPriorExpert`（继承自同一基类），强调其学习"全局先验"的语义 |
| 融合模块 | `SharedRoutedResidualFusion` → `branch_fusion` | 新增 `PriorSpecializedFusion`，将 shared/routed 重新表述为 prior/specialized |
| 路由专家池 | 硬编码 `TopKRoutedExpertPool` | `_resolve_routed_expert_pool()` 工厂方法，支持 `topk` / `conditional_specialized` |
| 共享专家 | 硬编码 `GatedCrossScaleSharedExpert` | `_resolve_shared_expert()` 工厂方法，支持 `gated_cross_scale` / `global_prior` |
| 融合模块 | 硬编码 `SharedRoutedResidualFusion` | 工厂方法，支持 `shared_routed_residual` / `prior_specialized` |
| 特征命名 | `z_shared`, `h_shared`, `h_route`, `h_route_proj` | 保留旧名兼容，新增 `h_prior`, `h_special`, `h_prior_refined`, `h_special_proj` |
| 辅助输出 | `x_hat_shared`, `x_hat_route` | 新增别名 `x_hat_prior`, `x_hat_specialized` |
| 配置字段 | — | 新增 `model_variant`, `shared_expert_type`, `routed_expert_type`, `fusion_type` |

**核心思想**：原来的 "Shared/Routed" 命名容易让人误解为平等的双分支，实际上 Shared 分支承担主体预测（约 95%），Routed 分支只贡献残差（约 5%）。新命名 "Prior/Specialized" 更准确反映这一非对称关系——Prior 提供稳定的全局先验，Specialized 提供条件化的局部修正。

## 2. 模型架构

### 2.1 总体数据流（v7-single 语义版）

```
输入: x_f_obs, m_f, x_m_obs, m_m, x_c_obs, m_c, r_m, r_c

  ScaleTokenEncoder ×3  →  h_f [B,64,T,H,W], h_m [B,64,T,H/2,W/2], h_c [B,64,T,H/4,W/4]
      │
  QualityRouter ×3  →  gate_f, gate_m, gate_c  [B,4]
      │
  ConditionalRoutedExpertPool (topk)  →  z_f, z_m, z_c    ← 条件化专家（Specialized 路径）
      │                                        │
      │                                   ProgressiveRouteFusion
      │                                        │
      │                                   h_special [B,64,T,H,W]
      │                                        │
      ├────────────────────────────────────────┤
      │                                        │
  ExpertEnhancedSharedInput (mode=pre)         │
      │                                        │
  GlobalPriorExpert                            │
  ├─ ReliabilityAwareScaleGate                 │
  └─ Conv1x1+2×ResBlock(concat(w·h))          │
      │                                        │
  h_prior [B,64,T,H,W]                         │
      │                                        │
      ├────────────────────────────────────────┤
      │                                        │
  PriorSpecializedFusion                       │
  h_prior → ResidualSTBlock → h_prior_refined  │
  h_special → Conv+ResBlock → h_special_proj   │  (+Dropout3d 0.1)
  h_main = h_prior_refined + α·h_special_proj  │  α = sigmoid(trainable)
      │
  pred_head → x_hat_main [B,C,T,H,W]
  shared_aux_head → x_hat_prior [B,C,T,H,W]
  route_aux_head → x_hat_specialized [B,C,T,H,W]
```

### 2.2 与 v6 的等价性

v7-single 默认配置（`shared_expert_type=gated_cross_scale`, `routed_expert_type=topk`, `fusion_type=shared_routed_residual`）与 v6 **计算等价**：

- `GlobalPriorExpert` 继承 `GatedCrossScaleSharedExpert`，forward 完全一致
- `ConditionalRoutedExpertPool` = `TopKRoutedExpertPool`（当 `routed_expert_type=topk`）
- `PriorSpecializedFusion` 与 `SharedRoutedResidualFusion` 的 residual 模式等价
- 特征字典同时保留新旧两组 key，保证向后兼容

### 2.3 默认超参数

| 参数 | 值 | 说明 |
|------|-----|------|
| dim | 64 | 隐藏维度 |
| num_experts | 4 | 专家数（3 尺度共享） |
| top_k | 2 | 每 token 激活专家数 |
| shared_expert_type | gated_cross_scale | → GlobalPriorExpert (GatedCrossScaleSharedExpert) |
| routed_expert_type | topk | → ConditionalRoutedExpertPool (TopKRoutedExpertPool) |
| fusion_type | shared_routed_residual | → SharedRoutedResidualFusion |
| scale_mode | fine_mid (TaxiBJ) / fine_mid_coarse (BikeNYC, CHAP) | 数据集特定 |
| shared_input_mode | pre | Prior 分支接收原始嵌入 |
| route_gamma_init | -3.0 | α 初始≈0.047 |
| route_dropout | 0.1 | Specialized 分支 Dropout3d |

## 5. 训练动态分析

### 5.1 TaxiBJ fixed rate=0.8 — 双尺度下的异常行为

```
Epoch   1: TrainLoss=86.08  TrainMAE=73.47  SclGateF=0.047  SclGateM=0.953  ← Mid 从一开始就主导
Epoch  20: TrainLoss=17.09  TrainMAE=13.91  ValMAE=22.79   SclGateF=0.000  SclGateM=1.000  ← Fine 权重归零
Epoch  80: TrainLoss=11.89  TrainMAE=9.92   ValMAE=10.12   SclGateF=0.000  SclGateM=1.000
Epoch 155: BEST ValMAE=8.997
Epoch 160: TrainLoss=10.15  TrainMAE=8.72   ValMAE=9.00    SclGateF=0.000  SclGateM=1.000
[Test]    MAE=8.592  RMSE=13.867  (Val→Test: −4.5%)
```

**关键发现**：`scale_mode=fine_mid` 下，`ReliabilityAwareScaleGate` 几乎将所有权重分配给 Mid 尺度（16×16），Fine 尺度（32×32）权重为零。这意味着模型实际在 16×16 分辨率上进行补全，然后上采样回 32×32——丢失了细粒度空间细节。

这与 v6 的 TaxiBJ（`scale_mode=fine_mid_coarse`）形成鲜明对比，v6 中 Fine 尺度权重始终为 1.0。

### 5.2 CHAP fixed rate=0.4 — 三尺度正常收敛

```
Epoch   1: TrainLoss=23.67  TrainMAE=20.03  SclGateF=0.068  SclGateM=0.899
Epoch  40: TrainLoss=8.94   TrainMAE=7.12   ValMAE=3.73    SclGateF=0.000  SclGateM=1.000
Epoch 100: TrainLoss=1.95   TrainMAE=1.91   ValMAE=2.59    SclGateF=0.000  SclGateM=1.000
Epoch 150: BEST ValMAE=0.836  (Val/Train = 0.78×)
[Test]    MAE=0.669  RMSE=0.961  (Val→Test: −20.0%)
```

CHAP 虽然也是 Mid 主导，但因为 PM2.5 数据本身空间平滑性强，16×16 分辨率已足够捕获区域级污染模式，因此性能未退化。

### 5.3 损失分解跨数据集对比（训练末期）

| 损失分量 | TaxiBJ f0.8 | BikeNYC f0.6 | CHAP f0.4 |
|---------|------------|-------------|----------|
| L_main | 8.25 | 1.03 | 0.71 |
| L_cross | 12.97 | 3.47 | 0.98 |
| L_shared_aux | — | — | — |
| L_route_aux | — | — | — |
| Route α | 0.112 | 0.062 | 0.063 |

### 5.4 scale_gate 行为总结

| 数据集 | scale_mode | Fine 权重（末期） | Mid 权重（末期） | Coarse 权重 |
|--------|-----------|-----------------|-----------------|------------|
| TaxiBJ | fine_mid | **0.000** | **1.000** | N/A |
| BikeNYC | fine_mid_coarse | 0.901 | 0.034 | 0.065 |
| CHAP | fine_mid_coarse | 0.000 | 1.000 | 0.000 |

**核心观察**：在 `fine_mid` 双尺度配置下，ReliabilityAwareScaleGate 系统性地将权重全部分配给 Mid 尺度。这可能是由于：
1. Mid 尺度的观测统计量（q_m）更"可靠"（更大的感受野 → 更高的有效观测率）
2. Fine 尺度的 mask_embed 引入了过多缺失噪声
3. 双尺度下 Mid 成为"最粗"尺度，占据了原 coarse 的全局先验角色

这一行为提示 `scale_mode=fine_mid` 可能不适合 TaxiBJ 这类需要细粒度空间细节的数据集。

## 6. 关键发现

1. **语义重构在计算等价的默认配置下验证通过**：BikeNYC 和 CHAP 表现与 v6 一致，证明模块重命名和工厂方法引入未改变模型行为。

2. **TaxiBJ 退化源于 `scale_mode=fine_mid`**：移除 coarse 尺度后，ReliabilityAwareScaleGate 将全部权重分配给 Mid（16×16），Fine（32×32）完全被忽略，导致空间细节丢失。建议 TaxiBJ 恢复 `scale_mode=fine_mid_coarse`。

3. **Prior/Specialized 命名更准确**：Route α 在所有数据集上为 0.05–0.11，Prior 分支贡献约 90–95% 的主体预测，Specialized 分支仅提供约 5–10% 的残差修正。

4. **CHAP 仍保持 Val < Train**（gap 0.78×），Test 优于 Val 约 20%，PM2.5 数据的高度可预测性不受语义重构影响。

5. **val_epoch=5 增加了验证频率**但训练动态无实质变化，最佳 epoch 分布与 v6（val_epoch=10）相似。
