# 20260928_第24版_四轮八专家搭档路由六组结果分析

## 1. 实验目的与设置

本次比较四轮八专家、每轮稀疏激活两个专家时，独立 MoE、共享原生 Top-2，以及三种搭档路由实现。核心问题是：共享专家的 CoE 能否优于独立 MoE；主专家先提出补全候选，再选择搭档是否优于原生 Top-2；搭档修正分数是否应该同时用于选择和融合；候选排名损失是否应该只更新搭档评分头。

六组均为 TaxiBJ 清洁数据，训练 2452、验证 342、测试 707 个窗口；输入为 `[B,2,12,32,32]`。训练、验证和测试均按同样的九种缺失类型、缺失率 0.4 构造 mask。训练 mask 每轮重采样；验证和测试各自固定，因此三者类型分布相同，但逐样本 mask 不相同。共同条件：seed 7、双卡 DDP、全局 batch 16、80 epoch、每 2 epoch 验证、AdamW 与 cosine 学习率计划、前 3 epoch 预热和接续 3 epoch 过渡、无早停。最佳模型由验证 MAE 选取，权重暂存在 CPU 内存中，最后仅测试一次，不生成 `best.pt`。

| 组别 | 模型与搭档策略 |
|---|---|
| M0：独立 MoE | 四轮各自拥有八专家池，个体 Router 原生 Top-2 |
| P1：旧搭档 | 共享专家池，主专家由个体 Router 选取，搭档由独立评分头选择；该头零初始化时不回退到原生第二名 |
| P2：残差搭档 | 共享池，搭档分数 `z_j+d_theta`，但组内融合仍使用原生 `z_i,z_j` |
| C0：共享原生 | 共享池，直接选原生 Top-2，无搭档头或候选排名监督 |
| C1：修正融合 | P2 的搭档分数同时用于搭档选择和融合，组内 softmax 输入是 `z_i,z_j+d_theta` |
| C2：评分头单独监督 | C1 基础上，候选排名损失使用停止梯度的骨干特征与原生 logits，使该项损失只更新搭档评分头 |

P1、P2、C1、C2 均每卡每 16 个 batch 试运行三个候选搭档，以隐藏训练目标产生排名标签，排名损失系数为 0.1；这四组比 M0/C0 有额外训练计算。第 2/3/5/6 组使用同一个八专家池和一个跨轮共享的搭档评分头。

## 2. 最新代码中的模型结构与训练目标

主模型为 `DualBranchSTImputer`，本组辅助补全支路关闭。输入 `x_f_obs` 与观测 mask `m_f` 进入四轮 `TemporalSpatialCoE`：先用观测值、mask、观测支持度和位置特征编码，再逐轮计算共享更新与路由专家更新，更新隐状态并解码。每轮有独立 Router；本组专家池包含 T、S、TD、SD、TA、ST、TL、SL。专家权重按组别跨轮共享或每轮独立。硬 Top-2 仅计算所选两个专家；搭档路由先执行主专家、形成临时提议，再执行选中的搭档。本组 Top-2 在预热期仍只选两个专家，调度主要改变路由温度和组内权重；不能把它解释成预热期激活全部专家。观测位置由原始观测值保留。显式补全反馈、接受门和多尺度均关闭。

C1/C2 的搭档评分头最后一层零初始化；初始修正为零时，选中的搭档与组内融合权重都回到原生 Top-2。后续修正既能改变第二位，也能在不改组合时调节第二位的融合权重。C2 仅在**候选排名损失分支**停止骨干特征及原生 logits 的梯度；主任务依然通过评分头、融合和专家更新正常训练骨干。当前损失为缺失位置 L1，加上候选重要性负载均衡项（系数 0.01）；搭档组另加上述排名损失。平衡项使用候选边缘重要性，软候选分布因策略不同而不同，不能把六组理解成完全相同的正则目标。

## 3. 完整性与主结果

六组回执均显示完成 80/80 epoch、40 次验证和一次最终测试；训练、验证、测试的 MAE/RMSE/loss 均有限值。未发现缺失测试记录。没有 `best.pt` 是配置所致，最佳权重来自 CPU 内存。MAPE 数值达到数十万量级，受零或近零目标影响，本报告不据此排序。

| 组别 | 参数量 | 最优 epoch | 最优验证 MAE | 测试 MAE ↓ | 测试 RMSE ↓ | 总时长 |
|---|---:|---:|---:|---:|---:|---:|
| M0 独立 MoE | 740,411 | 54 | 22.387 | 21.275 | 36.457 | 34.0 分钟 |
| P1 旧搭档 | 275,512 | 80 | 24.247 | 23.186 | 39.434 | 41.2 分钟 |
| P2 残差搭档，原融合 | 275,512 | 74 | 23.136 | 21.818 | 37.449 | 43.4 分钟 |
| C0 共享原生 Top-2 | 250,043 | 80 | 22.468 | 21.389 | 36.699 | 39.4 分钟 |
| C1 修正分数参与融合 | 275,512 | 70 | 21.785 | 20.446 | 34.665 | 43.8 分钟 |
| **C2 修正融合＋评分头单独监督** | **275,512** | **80** | **21.242** | **19.932** | **34.161** | **46.5 分钟** |

与 C0 相比，C1 测试 MAE 降低 0.942（4.41%）、RMSE 降低 2.034（5.54%）；C2 分别降低 1.456（6.81%）和 2.538（6.91%）。C2 比 C1 再降低 MAE 0.514（2.51%）、RMSE 0.503（1.45%）。与独立 MoE 相比，C2 MAE 降低 1.343（6.31%），参数少约 62.8%。但 C2 总训练时间比 C0 多 17.9%，比 M0 多 36.7%；本次记录的每卡每 batch 前向时延为 C2 61.26 ms、C0 53.40 ms、M0 52.06 ms。参数效率优势不等于计算时延优势。

M0 与 C0 测试 MAE 仅差 0.113；单个 seed 下不能认定共享/独立专家本身有稳定优劣。P1 比 C0 差 1.797，P2 缩小了退步，但仍比 C0 差 0.430。对搭档分数加入原生 logits 改善了旧实现；进一步让修正参与融合，才在这次实验中超过原生 Top-2。C1 相对于 P2 除组内融合权重外，也改变了候选边缘重要性及其 balance 梯度，因此此对照不能将全部收益严格归因于融合权重本身。

## 4. 路由与机制诊断

最值得注意的是，最优组 C2 在自身验证最优轮次相对于**该模型自身原生 Top-2**的逐轮组合分歧率为 **2.27%、5.40%、0%、0%**；C1 是 **5.11%、1.70%、0.57%、0.28%**。相比之下，P2 为 **76.52%、47.82%、6.25%、11.55%**，P1 为 **100%、33.24%、67.05%、94.60%**。这表明最优组并没有大量重新选择搭档。C1/C2 更可能从较稳定的原生选择、修正后的融合权重及其训练路径获益。各组的 Router 参数在训练中分别变化，因此“与自身 Top-2 分歧少”不等于组间使用了同一组专家，也不能单凭此指标量化选择与融合各自的因果贡献。

C2 最优验证轮次的搭档平均融合权重按四轮分别为 **0.441、0.386、0.334、0.324**，说明搭档并非只被选中却几乎不起作用。按至少 1% 被选率计算，四轮实际使用的专家种数分别为 **3、4、2、3**。第 1 轮始终包含 S，第 3 轮始终是 ST+SL；因此仍有明显的轮次偏好，不能宣称八种专家在每一轮都充分探索。C0 第 1、2 轮基本固定为 S+SL、TL+SL；M0 第 2 轮也完全固定为 TA+TL。路由集中本身并非任务失败证据，但对“自由组合”的解释必须保持谨慎。

C2 测试集按缺失类型统计，第 1 轮的主组合随模式变化：random_point 以 S+TA 为主（97%），node_outage 和 spatial_region 为 S+TL（均 100%），spatiotemporal_block 主要为 S+TA（73%）；第 2 轮也出现 SD+SL 与 T+SD 等差异。第 3 轮的 ST+SL 在九类缺失中约占 99%–100%。这说明前两轮存在一定条件选择，但还没有按缺失类型的误差消融来证明这种选择就是性能来源。

**梯度诊断限制：** 当前配置虽然设置每 64 个全局 batch 记录一次主损失与排名损失的梯度夹角，但候选探针只在每卡 `batch_index % 16 == 0` 时运行。每轮每卡 154 个 batch，代码中的诊断条件 `((epoch-1)*154 + batch_index + 1) % 64 == 0` 在探针步上始终为奇数，因而从不触发。日志没有这两项损失在骨干上的梯度方向证据。C2 更优与“隔离排名梯度有益”相容，但不能据此断定 P2/C1 已出现梯度冲突。

## 5. 训练与验证轨迹

所有组在前 40 epoch 快速下降，随后继续改善，没有 NaN 或明显发散。验证 MAE 在第 20/40/60/80 epoch 的轨迹如下：

| 组别 | e20 | e40 | e60 | e80 |
|---|---:|---:|---:|---:|
| M0 | 32.94 | 24.20 | 22.76 | 22.41 |
| P1 | 35.50 | 29.05 | 25.85 | 24.25 |
| P2 | 32.63 | 26.53 | 23.91 | 23.19 |
| C0 | 32.04 | 25.96 | 23.56 | 22.47 |
| C1 | 35.09 | 26.64 | 22.34 | 22.02 |
| C2 | 32.15 | 24.25 | 21.76 | **21.24** |

C2 在 40 epoch 后持续改善，并在最后一次验证达到最优；目前没有看到其验证误差反弹，但不能推断 80 epoch 已完全收敛。C1 在 70 epoch 达到最优 21.785，80 epoch 为 22.018，出现轻微反弹。M0 在 54 epoch 达到最优 22.387，80 epoch 为 22.409，变化很小。P1 到 80 epoch 仍在下降，但从第 20 epoch 起明显落后于 C0/C2。训练 mask 每轮重采样，验证/测试 mask 固定，因而同一 epoch 的训练与验证 MAE 不能直接解释为常规同分布泛化间隙；六组的测试 MAE 都低于最优验证 MAE，提示测试划分可能相对容易。验证与测试的最终组别排序基本一致，C2 都是最优。

## 7. 结论与下一步

这次单 seed 实验为 **C2 作为下一轮主候选** 提供了较强的阶段性证据：它同时取得六组最低的验证 MAE、测试 MAE 和测试 RMSE，用约 27.6 万参数优于 74.0 万参数的独立 MoE。但它的训练/前向更慢，且组合与自身原生 Top-2 的差异很小，当前证据支持“有用的搭档条件修正与融合训练”，尚不足以证明“自由改选大量专家”是性能提升的核心原因。

下一轮优先做三项小规模、同预算验证：① 对 C0、C1、C2、M0 增加至少两个配对 seed，报告均值和波动；② 固定原生 Top-2 的两个身份、仅允许修正搭档融合权重，与 C1/C2 对比，以分离“改选”与“改权重”；③ 修复梯度诊断触发条件，并记录每轮、每缺失类型的误差和路由，确认 C2 的优势是否真来自条件选择或辅助损失梯度隔离。若以推理效率为目标，还应在相同硬件上单独重复测量前向时延。
