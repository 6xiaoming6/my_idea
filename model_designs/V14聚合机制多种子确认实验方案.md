## 1. 范围与时间约束

本轮保留原 V14 代码和先前的聚合探针代码，新增独立确认入口。使用原 V14 的基础残差时空块，构建受控的细粒度—粗粒度聚合补全网络，**不是完整 V14 模型的消融，也不是论文全部缺失率的最终实验**。

目的不是再通过反复追加 epoch 找到一次提升，而是排除“只是邻域变宽”“只是学到全局权重”“只是看到邻域内容”这三个替代解释。对照组、种子、训练预算在看新结果前固定。

单 GPU0 / RTX 3090 于 2026-09-09 11:00 左右进行真实数据批次计时。使用 1 次预热、3 次训练/评估批次的中位数外推，再加入检查点开销及 35% 余量：

|配置|每数据集训练窗口|验证/测试|实验数|预计总时间（含余量）|
|---|---:|---|---:|---:|
|默认 budgeted|256|全量|90|约 3.41 小时|
|`--profile full`|原始训练集全部窗口|全量|90|约 24.25 小时|

## 2. 五个核心对照

共同使用 dim=16、空间粗化步幅 2/4、同一细粒度与补全主干。三个聚合专家使用半径 0/1/2 的候选粗节点邻域；它们不是三个独立的重型补全网络。

|变体|聚合及路由方式|回答的问题|
|---|---|---|
|`single_wide`|只使用半径 2 的内容相关软分配|单一宽邻域是否已足够？|
|`uniform`|半径 0/1/2 聚合结果等权组合|多个邻域组合是否优于只用最宽邻域？|
|`static_moe`|每个尺度学习一组全局三专家权重|收益是否只来自静态权重学习？|
|`context_moe`|观测特征的局部均值作为点路由输入|邻域内容是否足以解释自适应路由收益？|
|`geometry_moe`|在同样的局部均值输入中加入掩码密度及空间差分|显式缺失几何能否带来额外收益？|

`context_moe` 和 `geometry_moe` 使用同参数量的 1×1 路由头。后者将三种邻域观测密度与两个方向的密度差分加入前五个特征通道，不增加可训练层。前者也使用掩码进行观测均值计算，不能称为“完全不使用缺失信息”；正确表述为“无显式几何统计注入”。这种参数无关的注入仍属于待验证设计，不能预先认定其有效。

`static_moe` 每个尺度有三个全局 logits。旧探针的点路由在缺失位置可能退化为相同输入，本轮加入静态对照，并让新的动态路由看到邻域观测信息。仅证明门控变化不等于证明门控有效。

`single_wide` 的实际聚合只用最宽邻域，但当前复用父类候选计算后再截取权重，因此不使用它证明计算速度优势。

## 3. 数据、重复与训练策略

- 三个数据集：BikeNYC、TaxiBJ、CHAP。
- 两种等缺失数量的空间几何：`scattered` 与 `block`，缺失率 0.4，空间掩码沿时间重复。它们是机制实验的人工掩码，**不等同于原项目 fixed/random CSV 实验**。
- 三个训练种子：42、2026、3407；共 5×3×2×3=90 组。
- 掩码种子固定为 1729，训练/验证/测试使用独立偏移；同一数据点跨变体、跨训练种子使用相同掩码。因此三种子主要估计初始化和训练顺序的波动，不代表三个独立缺失图样集合。
- 原训练/验证/测试划分不混用。默认从原训练集等间隔取 256 个窗口；全量配置不截取。验证和测试均使用各自原始划分的全部窗口。

|数据集|原训练窗口|默认实际训练窗口|验证窗口|测试窗口|
|---|---:|---:|---:|---:|
|BikeNYC|511|256|73|147|
|TaxiBJ|2491|256|356|712|
|CHAP|2626|256|322|322|

每组完整训练 80 epoch，不早停；每 2 epoch 进行一次完整验证，最后一轮确保验证。batch_size=16，AdamW，lr=0.001，weight_decay=0.0001，grad_clip=1.0，余弦学习率退火到 1e-6。优化损失为归一化缺失位置 Smooth L1；MAE/RMSE 在原始数据范围的缺失位置计算，按元素总和累计，不等权平均各批次指标。

仅以验证集 MAE 选择参数；每次改善原子覆盖 `best.pt`。训练结束重新加载它，测试集只评估一次。旧实验不会因名称相似而复用：样本预算、掩码种子、模型配置、训练参数、源码和运行时版本均进入完成标识。未完成运行保留，重启在新时间目录从头训练该组，不声称恢复优化器状态。

## 4. 预先固定的分析顺序

1. 比较 `uniform` 与 `single_wide`，先判断多邻域组合是否必要。
2. 比较 `static_moe` 与 `uniform`，判断学习全局比例是否已足够。
3. 比较 `geometry_moe` 与 `static_moe`，判断位置相关路由是否有额外价值。
4. 比较 `geometry_moe` 与同容量的 `context_moe`，检验显式几何统计而不只是邻域内容。
5. 查看验证期和最佳模型测试期的缺失位置路由均值、标准差。标准差大于零只说明权重存在差异，不能作为有效性结论。

所有选择先看验证集的配对相对 MAE/RMSE：按数据集、缺失几何分别汇报三种子均值、标准差、胜出数，不直接平均三个数据集的原始 MAE。不把三种子当成充分的统计显著性证据。测试指标用于最终报告，不用于重选种子/epoch/对照组。

支持继续完整模型研究，需要多个数据集、两种几何下方向较一致，并且没有被 MAE 掩盖的严重 RMSE 退化；只有单点提升应表述为局部线索。若几何路由不优于静态或内容路由，应承认当前“几何特异性”解释不成立，而不是继续追加 epoch 寻找有利测试结果。

即使通过本轮，仍需后续完整模型实验、更多缺失率以及独立缺失图样，才能支撑更一般的结论。

## 5. 执行命令

在项目内层 `my_idea` 目录执行，激活 `difftdi`。只占用指定的一张 GPU，不修改功率上限、不启动 DDP。

只列计划或重新测时：

```bash
python scripts/v14-exploration/run_aggregation_confirmation.py --gpu 0 --dry-run
python scripts/v14-exploration/run_aggregation_confirmation.py --gpu 0 --calibrate --ignore-deadline
```

执行默认 256 训练窗口的 90 组确认（明确接受超过今日 13:00）：

```bash
python scripts/v14-exploration/run_aggregation_confirmation.py --gpu 0 --ignore-deadline
```

执行全量训练/验证/测试的 90 组确认（约一天，非今日 13:00 完成）：

```bash
python scripts/v14-exploration/run_aggregation_confirmation.py --gpu 0 --profile full --ignore-deadline
```

后续重复同一个命令会跳过完整匹配且训练/验证/测试记录齐全的组。运行前仍应确认 GPU0 没有其他大任务。不要在同一输出目录同时启动两个相同队列。

汇总时 profile 必须与运行时一致：

```bash
python scripts/v14-exploration/run_aggregation_confirmation.py --summary
python scripts/v14-exploration/run_aggregation_confirmation.py --profile full --summary
```

所有结果位于 `outputs/v14-exploration/aggregation_confirmation/`。每组目录包含 `config.json`、`best.pt`、`result.json` 与 `logs/train.log`、`val.log`、`test.log`、`metrics.jsonl`。路由统计在 `metrics.jsonl` 和 `result.json` 中；全队列汇总保存为顶层带时间戳的 `.log`/`.json`。计时单独记录在 `calibration/`，不作为已完成精度实验。
