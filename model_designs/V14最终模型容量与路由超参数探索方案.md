# V14最终模型容量与路由超参数探索方案

## 1. 目的

在不改变V14数据、损失、训练/验证/测试流程和模型计算图类别的前提下，验证现有结果是否受模型容量或MoE路由容量限制。所有候选均从原始V14独立训练，只改变一个已有JSON超参数，不继承E02、RLB、MCG、ESAP或BRLG。

## 2. 不变量

- 相同NPZ和离线fixed/random掩码；
- 相同seed=42；
- 相同Smooth L1与V14完整损失；
- 相同AdamW、学习率、余弦调度、AMP和梯度裁剪；
- TaxiBJ/BikeNYC/CHAP分别训练160/140/150 epoch；
- 按5/2/5 epoch验证；
- 仅按验证MAE覆盖一个`best.pt`，最后加载它测试一次；
- 不组合多个候选，不依据测试指标挑选候选。

## 3. 单变量候选

| 候选 | 唯一改动 | 原始值 | 新值 | 假设 |
|---|---|---:|---:|---|
| H01 | `model.main.dim` | 64 | 48 | 更小宽度抑制过拟合 |
| H02 | `model.main.dim` | 64 | 80 | 适度增加时空表征容量 |
| H03 | `model.main.dim` | 64 | 96 | 检验明显容量上限 |
| H04 | `model.main.num_experts` | 4 | 3 | 减少专家冗余和路由不稳定 |
| H05 | `model.main.num_experts` | 4 | 6 | 增加模式专门化容量 |
| H06 | `model.main.top_k` | 2 | 1 | 强化专家专门化 |
| H07 | `model.main.top_k` | 2 | 3 | 增加专家混合平滑性 |
| H08 | `model.v14.refiner_hidden` | 32 | 24 | 更保守的粗到细修正器 |
| H09 | `model.v14.refiner_hidden` | 32 | 48 | 适度增加重建容量 |
| H10 | `model.v14.refiner_hidden` | 32 | 64 | 检验重建分支容量上限 |
| H11 | `model.v14.prediction_embed_dim` | 16 | 8 | 压缩跨阶段预测信息 |
| H12 | `model.v14.prediction_embed_dim` | 16 | 32 | 扩大跨阶段预测信息 |
| H13 | `model.v14.controller_hidden` | 64 | 32 | 简化样本级安全门控 |
| H14 | `model.v14.controller_hidden` | 64 | 96 | 增强门控条件拟合能力 |
| H15 | `model.v14.correction_hidden` | 16 | 32 | 增加最终残差适配容量 |

H03和H05资源需求最高，训练脚本将它们放在最后。Top-K实现会计算全部专家，因此H06/H07主要改变路由融合，不会按Top-K比例降低计算量。

## 4. Core-6预筛

每个候选运行以下6个代表点：

1. TaxiBJ fixed@0.4；
2. TaxiBJ random@0.4；
3. BikeNYC fixed@0.6；
4. BikeNYC random@0.8；
5. CHAP fixed@0.2；
6. CHAP random@0.4。

共`15 × 6 = 90`组完整实验。H03在TaxiBJ上的1 epoch真实烟雾测试峰值显存为16.74GB，单epoch约60秒；据此结合原始V14实测耗时，整批预计约76小时，即约3.2天。运行器可恢复，完整任务会自动跳过；单个失败不会阻止后续候选，最终以非零状态列出失败任务。

## 5. 预注册晋级条件

只读取最佳检查点对应的验证指标。相对原始V14，候选必须同时满足：

1. 至少4/6点的验证MAE改善不小于0.5%；
2. 验证MAE宏平均改善不小于1%；
3. 验证RMSE宏平均退化不超过0.5%；
4. 任一点MAE退化不超过3%；
5. 任一点RMSE退化不超过5%；
6. 任一数据集两点平均MAE退化不超过0.5%。

若多个候选通过，先按验证MAE宏平均排序；差距不超过0.2个百分点时优先参数量更小者。只允许一个候选进入三种子确认，不组合候选。

## 6. 执行顺序

```bash
# 先执行一组最重候选的一轮流程烟雾测试
python scripts/v14-exploration/run_hparam_exploration.py \
  --gpu 0 --phase screen --candidates H03 --epochs 1 --max-jobs 1

# 正式90组Core-6；不要写--epochs
python scripts/v14-exploration/run_hparam_exploration.py \
  --gpu 0 --phase screen

# 全部完成后冻结验证集结论
python scripts/v14-exploration/summarize_hparam_screen.py
```

若且仅若汇总脚本推荐一个候选，再运行：

```bash
python scripts/v14-exploration/run_hparam_exploration.py \
  --gpu 0 --phase multiseed --candidates HXX --seeds 42 2026 3407
```

若没有候选通过，停止该路线并保留原始V14，不再根据测试结果追加插值候选。
