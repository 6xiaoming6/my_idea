# v24-COE 可行性评估与下一轮实验方案

**评估日期：2026-09-20**  
**研究对象：Temporal-Spatial Chain-of-Experts，用于时空数据补全**  
**评估依据：七份已上传实验报告，以及在线读取的 `v24-COE` 分支核心源码。**

> **结论：值得继续做一轮有明确决策标准的机制验证，但目前还不能将“动态链式重路由已经有效”视为成立。下一步不应继续围绕路径数量、专家均匀性或增加模块调参，而应区分收益来自专家池、空间感受野、训练预热、连续融合，还是输入条件化的链式决策。**

---

## 1. 评估范围与证据边界

本次阅读的报告包括：双 mask 自由路由与固定链、BikeNYC 核心 55 组、TaxiBJ 路由坍塌诊断、ABCDE 五组对照、七组路由诊断、第二轮路由探索及全部实验综合分析，编号见文末。[R1–R7]

在线逐文件读取了模型、专家算子、训练循环、损失、mask 生成器、实验计划生成器、mask 面板评估器、checkpoint 工具及若干实验补丁。**没有在本地完整克隆并运行仓库，也没有取得服务器上的原始 NPZ、完整日志和 checkpoint。因此，数值结果来自用户报告；当前实现结论来自在线源码；没有独立复算每个实验指标或验证当前源码与每个历史运行的 SHA-256 一致。**

后文严格区分三类内容：

- **报告事实**：原报告给出的指标、路由统计及完成状态。
- **代码核对与推断**：当前源码中可直接看到的执行方式，以及据此作出的逻辑推断。
- **建议实验**：尚未执行、不能当作已经有效的研究方案。

这里评估的 CoE 是 *Chain-of-Experts: Unlocking the Communication Power of Mixture-of-Experts Models* 中的神经网络专家链，不是同名的多智能体运筹建模方法。[P1]

## 2. 是否继续：应分成三个问题回答

### 2.1 研究问题是否值得做？——值得

“不同缺失条件下是否需要不同的时空处理链”是可检验的问题。最新混合缺失实验中，第三层在随机点/时间段缺失与节点/区域/条带缺失之间表现出明显不同的选择，这为继续检验提供了具体入口，而不是只有概念动机。[R1]

### 2.2 当前模型是否有性能潜力？——有初步信号

最新同轮对比为：

| 协议 | 自由路由＋预热 MAE | 验证选出的已测最强固定链 MAE | 相对改善 | 自由路由测试路径 |
|---|---:|---:|---:|---|
| 九类混合缺失 | 35.1400 | 37.2384 | 5.635% | 13 条，最大占比 21.22% |
| 单一随机点缺失 | 7.5326 | 7.5673 | 0.458% | 1 条，占比 100% |

两行对应不同的任务协议，不能直接横向比较 MAE 35 与 7。所有实验为 seed 7，且这一轮只有 20 epoch。[R1]

### 2.3 当前是否已经具备充分的论文机制证据？——还没有

当前的关键空缺不是“没有观察到多路径”，而是：

1. 强固定链覆盖不足，尤其没有包含 SD 的有竞争力链；
2. 未在最新四轮六专家配置下证实逐步读取新状态的路由必要性；
3. 尚未排除四轮连续融合或非条件化融合就能解释收益；
4. 没有充分训练、多随机种子和同协议外部基线的证据。

因此，应当把当前阶段视为**值得继续的候选方法，而不是已经可以围绕既定结论写论文的最终模型**。

## 3. 七份报告合起来，真正支持了什么

### 3.1 证据不是随着实验组数自动变强

主要已完成阶段合计为 55＋5＋7＋3＋16＝86 组运行，但它们改变了数据集、专家数量、链长、mask 分布、训练预算和部分实现，并且基本都是同一个模型随机种子。因此，86 组不能理解为 86 次独立验证同一结论。[R2,R4,R5,R6,R7]

| 阶段 | 最有价值的发现 | 不能据此推出 |
|---|---|---|
| BikeNYC 55 组 | 更新后的专家输入通常有用；两轮 Soft 在时空块和混合缺失上较强 | 最新四轮硬路由方案已跨数据集有效 |
| TaxiBJ ABCDE | 路由多样性与精度可分离；训练任务分布显著影响结果 | 九类训练一定好或一定坏 |
| 七组路由诊断 | 短期软预热方案优于原始硬路由 | 每个预热子组件均有效 |
| 第二轮探索 | 固定第二层 TA 后结果接近；修正噪声没有解救前两层 | 必须让每层都多样化 |
| 双 mask 固定链矩阵 | 混合协议优于已测固定链；随机点趋向统一链 | 已超过最佳可能固定链；全部提升均来自动态选择 |

### 3.2 当前最强的正信号

七组诊断的 R1 相对 R0，在九类混合缺失中将测试 MAE 从 41.450 降至 34.716；最新双 mask 轮次又显示主方案 35.140 优于本轮固定参照 37.238。不同轮次的具体数值不要混成一个统一排名，但“预热方案较原始硬路由更值得保留”的方向一致。[R1,R6]

最新混合协议的第三层，随机点和时间段缺失全选 ST；节点、区域、条带分别有 81.0%、70.9%、61.5% 选择 SD。第四层这些空间缺失族全选 ST，而时间段缺失约 88.6% 选择 TA。这是有条件相关性的路由行为；它尚不是所选专家更优的直接证明。[R1]

### 3.3 当前最重要的负证据

BikeNYC 上，将 router 输入固定为初始状态之后，多数协议相对 Full 的 MAE 差距不足 1%，混合缺失还略好。虽然这批实验有历史 AMP 干扰、配置也不同，它仍提醒我们：**“专家读取更新状态”与“router 必须读取更新状态”不是同一个命题。**[R2]

另外，两轮 Soft 在时空块和混合缺失上的 MAE 相对硬路由分别改善 18.22% 和 17.26%。不能只引用其正面部分来支持“链有价值”，却不在当前模型中补充同深度 Soft 基线。[R2]

## 4. 比原报告结论更值得追查的四个问题

### 4.1 随机点的 0.46% 改善，不是在线自适应选择的证据

**报告事实：**最新随机点实验中，自由路由模型对全部 707 个测试窗口都选择 `TA→ST→S→TA`。[R1]

**代码事实：**硬推理使用 argmax 和 one-hot，专家输出没有再乘一个因样本变化的软概率幅度；router 在此主要决定选谁。[C1]

因此可以直接推导：在同一个 checkpoint 上，将每个样本的执行路径强制设为该链，理论上应与自然硬路由输出一致，允许浮点实现误差。

换言之，这 0.46% 差异可能来自训练过程中的软预热、随机选择、专家训练经历、优化轨迹及随机性，但**不能解释成该测试集上逐样本选择不同链的收益**。

这不说明模型失败；它说明在该任务上应讨论“学习一个有效统一链”，而不是“测试时动态适应不同样本”。

### 4.2 最大混杂可能是空间感受野，而不仅是“少测了 SD”

源码中，S 的空间卷积为 3×3；SD 使用 dilation=2 的空间 3×3 卷积；ST 使用局部 3×3×3 卷积；TA 在同一空间节点内对整个时间窗做注意力。编码、状态投影、共享专家和解码都是点级空间操作。[C1,C2]

在默认核大小下，**给定一条硬路径，只看观测数值沿专家算子传播的空间支持范围**，每一步的空间最大半径增量为：

| 专家 | 空间半径增量 |
|---|---:|
| T、TD、TA | 0 |
| S、ST | 1 |
| SD | 2 |

所以，当前强固定参照 `TA→ST→S→TA` 的空间传播最大半径约为 2 个网格；一个示例候选 `S→TA→SD→ST` 的最大半径约为 4 个网格。

这只是结构推导，不是已经测得的有效感受野；膨胀卷积的采样也不等于稠密大核。router 的全局汇总能影响选路，因此不能把整张网络无条件地说成完全局部。但它确实揭示了一种替代解释：

> 混合缺失收益可能部分来自“选择了能够从更远处传播空间信息的算子”，而不一定来自“反复依据中间状态决策”。

**实验含义：**补强固定链时，必须覆盖 SD，并控制专家集合、出现次数和总感受野。仅继续增加 `T×4`、`S×4` 这样的弱链，无法排除这个解释。

### 4.3 需要区分“输入条件化选链”和“状态反馈重路由”

它们分别是：

\[
\text{初始条件路由：}\quad e_k = r_k(H_0,V_0,M),
\]

\[
\text{状态反馈路由：}\quad e_k = r_k(H_{k-1},V_{k-1},M).
\]

前者仍然可以让不同窗口执行不同路径，而且专家可以继续读取更新状态。只有后者额外主张：上一轮处理之后出现的信息，足以改变下一步更合适的选择。

若最新模型的 `router_state=initial` 与动态版相当，甚至更好，应该收窄论文表述为“缺失条件化专家链”，而不是继续宣称“逐步重决策不可替代”。

### 4.4 窗口级路由可能只是识别缺失模板

当前主方案是**每个窗口每一轮选一个专家**，不是逐节点、逐时刻或逐区域路由。mask 生成器在窗口间均衡分配九类几何族，标签用于日志而不是模型输入。[C1,C4]

这是合法的实验设计，不是标签泄漏。但仍需区分：模型是在识别相对容易辨别的几何模板，还是确实根据当前样本中可利用的观测信息作出更细致的恢复决策。

区分办法不是再增加类别数量，而是：同窗口换 mask、同缺失族内打乱路径、仅由 mask 支撑统计路由，以及保持输入初始状态路由。若这些更简单方式已经足够，就不应把所得效果包装成更强的反馈推理机制。

## 5. 当前代码核对：哪些问题已修，哪些能力已具备

### 5.1 不应继续把已修复的 GradScaler 问题列为首要改造

当前 `scripts/train.py` 在 epoch 循环外创建 scaler，并传给 `train_one_epoch`；`engine.py` 对未显式传入的调用也会在 optimizer 上缓存 scaler。[C3]

因此，旧 BikeNYC 结果需要数值稳定性复核，但**不能据旧报告断言当前代码仍然每轮重建 scaler**。当前重点是记录实际 AMP 跳步、检查有限值和做小规模 FP32 参照，而不是重复改一次同样的状态管理。

### 5.2 当前主实现仍是 Top-1，不是 Top-2

当前硬训练是 Gumbel straight-through 单选，硬推理是 argmax；`top12_margin` 只是前两名 logit 差距的诊断量，不表示激活两个专家。已提供的正式报告也没有给出同预算 Top-2 对照结果。[C1,R1]

### 5.3 观测保护是已有的正确设计，但不是新增贡献

原始 mask 保持固定，每轮补全状态只在缺失处采用预测值，观测位置使用真实可见输入。这避免把估计值当成新观测。[C1]

但这一机制的存在，不能自动证明进行了显式不确定性建模或可靠性传播；当前代码中的支持特征与预测变化量，不等于经过校准的置信度。

### 5.4 关键机制消融入口已经存在

`build_experiment_plan.py` 已定义 `coe_validation`，包括 `coe_initial_router`、`coe_initial_expert`、`coe_no_balance` 等补丁；对应补丁分别改变 `router_state`、`expert_state` 和均衡系数。[C5,C6]

七份报告中没有给出这些对照在最新四轮软预热配置下的完整结果。因此优先复用已有入口；若服务器已有完成日志，直接导出核对，不应因为报告未包含而机械重跑。

### 5.5 checkpoint 必须区分评估与完整恢复

报告显示 route20 七组保存了 best checkpoint；后面的 route20_next 和 dual-mask 主批次仅保留训练进程中的 CPU 最优状态，进程退出后不能从指标日志重建模型。[R1,R5,R6]

当前 `checkpoint.py` 保存模型、optimizer、epoch、指标与配置，但没有保存 scheduler、GradScaler 和各随机数生成器状态。[C7]

这对加载模型做评估足够；若要严格比较“共同预热后分叉训练”，则还需保存 scheduler、scaler、Python/NumPy/Torch/CUDA RNG、数据加载随机状态，并恢复 mask 日程与路由 epoch。

### 5.6 固定链不能直接照搬软预热配置

当前模型约束：非零软预热日程只允许 `routing_mode=hard`。现有固定链补丁明确把预热与过渡设为 0。[C1,C6]

因此，“给固定链也加同样 warmup”不是只改两个整数即可。真正匹配训练经历的做法，是从共同的预热结束 checkpoint 分叉，再分别继续自由路由和固定路径训练，并完整恢复训练状态。

## 6. 下一步第一优先级：用已有权重做路由干预

### 6.1 优先利用什么

优先使用 route20 的 R1 best checkpoint，按照它保存的配置及匹配源码加载，在验证集做诊断。它不是最新 dual-mask checkpoint，因此不要把它的干预结果写成“解释了 35.140 这一模型”。若需要针对最终配置，重跑时必须保存 best.pt。[R6,C7]

### 6.2 最小干预集合

| 干预 | 保持什么 | 改变什么 | 回答的问题 |
|---|---|---|---|
| 自然路由 | checkpoint、输入、mask | 无 | 原始参照 |
| 原路径重放 | 同上 | 强制执行该样本原先完整路径 | 干预实现是否正确 |
| 全局固定链 | 同上 | 所有样本执行验证选定的同一链 | 推理阶段个体化选路是否有增益 |
| 跨样本完整路径打乱 | 专家使用频率、完整路径多重集 | 路径与样本的对应关系 | 条件匹配是否有用 |
| 同缺失族内路径打乱 | 缺失族、路径总使用频率 | 族内样本与路径对应关系 | 是否超越粗粒度模板识别 |
| 仅替换第二步为 TA | 模型其余参数 | 第二步强制执行，后续重新前向 | 第二步路由的实际必要性 |

完整路径打乱应搬移整条长度为 4 的路径，而不是分别独立打乱每一层，以免额外创造未曾出现过的专家顺序。可以重复若干次排列观察稳定性。

所有替换都必须**重新计算被改变路径下的隐藏状态、解码值与后续计算**。仅修改日志中的 `paths` 字段而不改变实际执行，不是干预。

原路径重放应与自然路由近乎一致，先通过这一单元测试，再解读其他干预。

### 6.3 如何解释结果

定义同 checkpoint 下的路由替换差值：

\[
\Delta_{\mathrm{replace}} = \operatorname{MAE}_{\mathrm{replace}} - \operatorname{MAE}_{\mathrm{learned}}.
\]

- 跨族打乱明显恶化、族内打乱基本不变：支持粗粒度缺失条件相关，不支持更强的族内样本自适应主张。
- 跨族和族内打乱都稳定恶化：对细粒度条件匹配更有支持。
- 全局强固定链或打乱几乎无损：当前路由多样性未体现出足够的任务收益。
- 第二步固定 TA 近乎无损：无需为追求每层多样性继续加正则。

**限制：**同 checkpoint 干预会使专家遇到与训练时不同的中间状态，受专家共适应影响。因此它证明的是该已训练模型对原路径匹配的依赖，不等于证明所有重新训练的固定模型必然更差。必须配合从头训练的强固定链。

## 7. 最关键的下一轮训练：先四组，再补四组

### 7.1 先确定强固定候选，不做 6⁴ 全网格

四轮六专家共有 1296 种有序路径，但没有必要立刻全部从头训练。

在验证集上建立一个小候选集合：联合高频完整路径、逐层众数链、包含 SD 的路径、以及相同专家多重集的顺序置换。**联合最高频路径与逐层众数链不是同一概念；使用率高也不保证误差最低。**

可把 `S→TA→SD→ST`、`TA→SD→ST→TA` 作为结构示例，但它们不是报告已经确认的验证最优路径。最终候选由验证数据确定，不能从测试集低误差筛选。

### 7.2 首批四组

| 编号 | 模型 | 相对主方案的变化 | 判断作用 |
|---|---|---|---|
| A0 | 当前四轮六专家软预热主模型 | 无，保存完整权重 | 参照 |
| A1 | 初始状态 router | `router_state=initial`，专家仍读取更新状态 | 最直接检验状态反馈重路由 |
| F1 | 验证选出的含 SD 强固定链 | 固定路径，从头训练 | 排除固定链覆盖与感受野混杂 |
| F2 | 同专家多重集的另一顺序，或第二条强固定链 | 尽量固定专家出现次数，仅换顺序 | 检验顺序而非仅专家集合 |

这四组优先级高于继续增加噪声、历史身份嵌入、专家数、链长或多尺度。

### 7.3 随后补四组

| 编号 | 模型 | 相对主方案的变化 | 判断作用 |
|---|---|---|---|
| A2 | 四轮六专家条件 Soft | 每轮始终连续加权六专家，专家状态继续更新 | 硬选择是否真的必要 |
| A3 | 四轮全局可学习 Soft | 每轮一个不随样本变化的六维权重向量 | 条件路由是否胜过常量融合 |
| A4 | 无 balance 主模型 | 仅 `lambda_coe_balance=0` | 均衡项是否必要 |
| A5 | 初始专家输入 | `expert_state=initial` | 专家状态迭代的增量证据 |

A5 当前实现会同时冻结共享专家与路由专家读取的状态，不能把它描述为仅冻结路由专家。

**重要修正：当前主方案是四轮，Soft 和固定可学习混合控制也应首先做四轮。** 把四轮硬路由直接与两轮 Soft 对比，会重新引入深度混杂。单轮并行融合可保留为结构参照，但不是排除重复计算的最强控制。

A2 切换 `routing_mode=soft` 时，需将 hard-only 预热和过渡字段清零；A3 需要一个显式的、样本无关的每步权重参数实现，不能把现有条件 router 的平均输出误认为“全局常量权重”。

### 7.4 训练公平性

首轮保持共同清洁数据、同一套混合 mask、同一重采样日程、同 batch、相同名义更新预算和 LR 日程。对相同模块尽量配对初始化；mask、数据顺序与路由随机性最好有独立随机数流。

先以少量配置筛选，再将主模型、最强固定链和最有竞争力的简化模型扩展至至少 3 个预先选定的模型 seed。不要把同 seed 不同运行的 34.716、34.851、35.140 当作多 seed 均值。[R1,R5,R6]

正式较长预算可选择共同的 50 或 80 epoch，但应从同一起点采用同一个长预算学习率日程。不能把 cosine20 已衰减结束的模型随意续训，与从头 cosine80 的固定链混比。

## 8. 同 epoch 与同计算预算要分开报告

最新混合协议自由路由记录耗时为 31.86 分钟，强固定链为 9.90 分钟，约 3.22 倍；随机点对应约 3.50 倍。当前硬路由训练计算全部候选专家以获得直通路由梯度，固定链仅执行所选专家。[R1,C1]

这不意味着同 epoch 对比毫无价值；它控制了样本暴露次数。但它不能用于声称训练更省算力。

建议分别报告：

1. **相同样本/优化步数**：观察相同数据暴露下的学习效果；
2. **相同训练时间或 FLOPs 预算**：观察成本效益；
3. **独立推理测试**：固定硬件、batch、精度和预热，记录稳定统计，而不是引用一次测试总耗时。

固定链获得更多同时间训练步数时，也会看到更多重采样 mask；这是时间预算问题的一部分，不应伪装成仅改变路由的单变量实验。

## 9. mask 协议：保留混合任务，但补足控制

### 9.1 训练和测试匹配是一种任务定义，不是为了路由多样性改任务

若论文目标是“一个模型适应多种缺失结构”，九类混合 train/val/test 是合理主协议。若目标是特定部署场景或传统随机点基准，就应保留对应标准协议，不能只报告最容易体现多路径的条件。

ABCDE 的 D/E 是九类训练、随机点验证测试；最新 mixed9 则是同分布混合评估。它们回答不同问题，不能拿 D/E 的恶化否定 mixed9，也不能拿 mixed9 的收益抹去随机点迁移代价。[R1,R4]

### 9.2 最小二因素控制

| 训练缺失结构 | 固定训练 mask | 每 epoch 重采样 |
|---|---|---|
| 随机点 | RP-static | RP-resample |
| 九类混合 | M9-static | M9-resample |

当前双协议对比主要落在 RP-static 与 M9-resample 两个对角单元，同时改变了形态和刷新方式。[R1]

预算有限时，先让随机点与混合训练都采用重采样，保持各自验证/测试 mask 固定；随后只对主模型和最强固定链补完整二因素控制。

### 9.3 同窗口九类配对评估

当前 mixed 测试中每类只有约 78–79 个、且属于不同底层窗口。[R1]

建议在验证集先建立配对面板：对同一底层窗口施加九类固定 mask。除 MAE/RMSE 外，记录每族误差、逐窗口误差、路径、缺口长度、空间到观测的距离与流量范围。

`evaluate_mask_panel.py` 已经能逐族生成同协议面板并输出该族整体评估；可在其基础上扩展逐窗口结果和路径干预，不需要重新搭一套数据管线。[C8]

### 9.4 泛化检查的含义要准确

新的 mask seed 只检验同一生成分布下的随机几何泛化。更强的检查包括未训练的缺口长度、区域尺寸、缺失率或组合，以及其他数据集。

几何 mask 与数值独立，不等于“缺失完全随机”：结构化缺失中的多个位置存在相关性。也不要把这些合成族直接当成真实设备故障分布的已验证代表。

## 10. 主指标与统计：不能用路径数替代任务收益

建议以有效人工缺失点上的 MAE/RMSE 为主。整体 MAE 按误差和与有效目标数累积；另外报告逐族指标以及各族等权平均的 macro-MAE，并明确两者定义。[R1,R2]

对同窗口配对结果，可以计算：

\[
D_i=\operatorname{MAE}_i(\text{固定/简化模型})-
\operatorname{MAE}_i(\text{主模型}).
\]

记录平均差、分位数和获胜比例，而不只报一个总改善率。相邻窗口可能共享时间片；做置信区间时应考虑按连续时间块重采样，不能把数百万缺失点视为彼此独立样本。多 mask 面板上的同一窗口也不能拆成多个独立数据样本。

模型 seed 与 mask seed 需要分开：前者检查优化稳定性，后者检查缺失实现的敏感性。三 seed 只是起点，不保证所有小差异都可作显著性结论。

既有报告已反复观察测试表现。后续选模型、选链、调权重以验证集为主；每个运行只测试一次，不代表整个研究过程从未根据测试反馈调参。条件允许时，最终保留未参与设计选择的时间段；只更换 mask seed 并不等于重新获得完全未见的数据测试集。

## 11. 外部基线与跨数据集：不要等到最后才做

现有实验主要是内部结构对照，尚不能说明相对成熟补全方法的竞争力。[R7]

建议在完成首批机制诊断的同时，开始小范围移植：用户之前稳定的 v14、ImputeFormer，以及与时空专家最接近的 STAMImputer；GRIN 可作为图时空补全参照。[P2,P4,P5]

所有模型必须使用相同的清洁 split、输入窗长、可见值、mask 与指标单位，并获得合理调参预算。不能与论文中不同数据切分、不同缺失协议的表格数字直接计算优势。使用图模型时，需要明确网格到节点的映射以及邻接构造，不得利用测试真值构图。

跨数据集首先复核 BikeNYC 的最新四轮配置，而不是把旧两轮 Soft 的结果当成已经完成。若要主张“整个时空数据方向”的普适性，再选择与交通网格不同的数据类型；当前固定网格卷积实现不能不加说明地冒充任意图结构实现。

## 12. 创新性：可以保留什么，不应写什么

### 12.1 已有工作的边界

CoE 原论文已有迭代专家执行、独立路由和残差状态传递；STAMImputer 已研究时空专家调权及块缺失问题；CP-MoE 已在交通拥堵预测中使用专家级联。[P1,P2,P3]

本次针对性检索没有为“这是该领域第一次使用这一完整组合”建立充分证据，所以不建议使用未经系统排查的“首次”。这也不等于已找到与你实现完全相同的方法。

### 12.2 当前可用的保守表述

> 针对异质缺失条件，构建共享异构时空算子的多步专家链，并利用短期连续混合改善专家训练机会；在当前 TaxiBJ 混合缺失实验中，形成缺失条件相关的路径选择，并优于多条预指定固定链。

这与报告吻合，但还不是最强的最终论文贡献。

### 12.3 需要下一轮证明的更强表述

> 不同缺失条件下，可用观测的传播方向与作用范围不同；模型根据初始观测及逐步更新状态选择恢复算子与组合顺序，且这种条件决策在专家集合、深度和预算控制后仍优于固定或非条件化组合。

这里的每一项都对应可失败的对照，而不是只依赖可视化解释。

### 12.4 综合报告中两处应收紧的说法

- “稳定的全局最优链”应改为“当前模型学到的统一链”或“已测候选中较强的固定链”。没有穷举或证明，不能称全局最优。[R7]
- BikeNYC 的“两轮始终 Soft”与 TaxiBJ 的“短期 Soft 后转硬”不是同一种训练/推理方案；前者不能直接充当后者的跨数据集复现。[R2,R7]

## 13. 继续、收窄或转向的决策表

以下是研究决策建议，不是保证结果的预测。

| 下一轮结果 | 解释 | 建议 |
|---|---|---|
| 主模型稳定胜强固定链、初始 router、非条件化融合；打乱路径也伤精度 | 状态条件化专家链获得较完整支持 | 继续，以机制和跨数据集验证为主 |
| 主模型胜强固定链，但与初始 router 相当 | 输入条件化有用，反馈重路由未证明必要 | 收窄为缺失条件化专家组合，不硬写逐步反馈 |
| 四轮条件 Soft 最强，且胜全局 Soft | 条件混合有用，硬离散不是当前最优实现 | 转向软链或稀疏软链，重新测推理成本 |
| 全局 Soft 与主模型相当或更强 | 主要收益可能是算子互补与反复更新 | 不以动态路由为主贡献 |
| 含 SD 固定链追平，且预算配对后动态无稳定优势 | 感受野/专家选择解释更强 | 优先简化结构；停止围绕现路由反复调参 |
| 候选路径的逐样本最优明显好于固定，但 learned router 没选好 | 路由有潜力，当前学习方式不足 | 再做有针对性的路由训练改进 |
| 强固定和简单融合在多 seed、多协议上均不差，且路径打乱近乎无影响 | 当前配置缺少动态链必要性 | 保留有用算子和迭代骨干，停止扩大 COE 路由主线 |

不建议预设“Full 必须在所有消融上第一”，再通过挑 seed 或挑 mask 让结果满足它。若某个简化模型持续更好，它应成为新的主模型，或者推动主张收窄。

## 14. 只有诊断支持时，再考虑这一项方法增强

### 14.1 候选：以剩余补全误差为监督的路由质量学习

如果候选路径之间确实存在样本相关优势，但当前 router 选择质量差，可以研究：不只让 router 通过主损失的直通梯度间接学习，而是为它增加由训练隐藏标签构造的“候选专家效果”监督。

最小实现从最后一轮开始：固定相同的第三轮状态，分别执行六个候选最后一步，解码并计算训练人工隐藏位置的 L1，得到六个标量损失。构造

\[
q_e=\operatorname{softmax}(-\operatorname{stopgrad}(\ell_e)/\tau),
\]

使用轻量的排序或分布匹配目标引导 router，并保留原补全主损失。

这样直接针对的是“选择是否有用”，而不是“选择是否均匀”。

### 14.2 不能越过的限制

训练隐藏真值只用于产生监督标签，不能作为路由输入。验证/测试的 oracle 仅作为标明的诊断，不得作为实际预测路径。候选标签要停止梯度，避免专家与评分目标相互投机。

早期专家的好坏应看后续完整链后的误差；只比较该步即时解码误差，可能偏向短视选择。对早期步骤做全后缀 rollout 会增加计算，不能因为当前前向计算了所有候选专家就声称该监督免费。

这只是候选改进方向，尚未在本项目验证，也未在本次检索中完成独立创新性查重。只有“存在可观候选选择空间但 learned router 选择不佳”的诊断成立时，才值得实施。

## 15. 给下一轮开发的任务清单

| 代码位置 | 优先改动 | 验收点 |
|---|---|---|
| `scripts/train.py` | 主方案保存 best.pt；需要分叉训练时另存完整训练状态 | 从已保存配置恢复后指标一致 |
| `utils/checkpoint.py` | 分叉/恢复场景增加 scheduler、scaler、RNG 与日程状态 | 不重置学习率或路由 epoch |
| `models/temporal_spatial_coe.py` | 增加评估专用按样本路径覆盖 `[B,K]`，与原路由日志区分 | 原路径重放输出一致；观测位置不改变 |
| `scripts/v24/evaluate_mask_panel.py` | 逐窗口与逐族误差、完整路径打乱、候选链回放 | 同一底层窗口和同一 mask 配对 |
| `scripts/v24/build_experiment_plan.py` | 主配置与消融配置自动差分白名单 | 防止再次出现“噪声组其实换深度/专家池” |
| `configs/v24/experiments/` | 复用 initial-router/no-balance 等入口，补强固定与四轮融合 | 最终生成配置而非补丁名称决定实验身份 |
| 评估输出 | 分离 MAE/RMSE、路由分布、训练成本与推理成本 | 不以路径熵替代补全质量 |

## 16. 最终建议

**保留当前四轮六专家软预热模型作为诊断主干，但暂停扩结构。**

先在保存权重上验证“路径与输入的对应关系是否有用”，再用最新配置验证初始状态 router、含 SD 强固定链和同深度融合。首批四组已经足以改变研究方向；后续四组用于解释收益来源。通过这些关口以后，再投入较长预算、多 seed、外部基线与第二数据集。

真正值得建立的结论不是：

> 模型能产生更多路径。

而是：

> **在同样的专家与合理预算下，为这个缺失条件选择这条恢复链，确实比固定组合或更简单的融合更准确；若声称逐步反馈有用，还必须证明读取中间状态比只看初始条件更好。**
