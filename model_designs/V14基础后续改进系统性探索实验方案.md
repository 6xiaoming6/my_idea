# V14 基础后续改进系统性探索实验方案

> 基础版本：`v14-single`  
> 当前基础提交：`4544e22`  
> 方案定位：先定位 V14 的真实瓶颈，再用单变量实验筛选改进，最后形成下一正式版本  
> 训练原则：所有候选模型仍采用单阶段、端到端训练，不使用教师模型、预训练、冻结/解冻或多阶段优化  
> 核心指标：原始范围 MAE 为主，RMSE 为必须满足的安全指标  

## 1. 总体建议

下一步不建议立刻编写一个包含多个新模块的 V20，也不建议继续从 V15～V19 中拼接结构。

更稳妥的路线是：

```text
固定 V14 基线和评估口径
        ↓
利用已有 checkpoint 做无训练诊断
        ↓
找出 correction、gate、尺度和误差尾部的真实瓶颈
        ↓
一次只改变一个因素
        ↓
在少量代表点完成完整训练筛选
        ↓
对候选进行多种子验证
        ↓
只把通过验证的一个改动写入下一正式版本
        ↓
运行 24 点全量实验
```

这里的“阶段”只表示实验执行先后顺序。每一组模型训练仍然是：

```text
随机初始化
→ 单阶段端到端训练
→ 定期验证
→ 只覆盖一个 best.pt
→ 加载 best.pt
→ 测试一次
```

## 2. 已有实验揭示的 V14 真实问题

### 2.1 V14 的优点

V14 仍是当前最合适的基础版本：

- 三个数据集均能稳定完成训练；
- 相对 main，BikeNYC 和 CHAP 有明确改善；
- 24/24 个实验中，V14 final 均优于同次训练的 `x_base`；
- 只复用一套 main Backbone，没有复制 Encoder 和专家池；
- 最佳 checkpoint 机制有效；
- 模型结构和论文解释相对完整。

### 2.2 Gate 与 correction 的尺度不可辨识

V14 的最终输出为：

```text
x_v14 = x_base + alpha_final × delta_ctf
```

现有 24 点日志显示：

| 诊断量 | TaxiBJ | BikeNYC | CHAP |
|---|---:|---:|---:|
| `alpha_mid` 均值 | 0.7932 | 0.7781 | 0.4499 |
| `alpha_fine` 均值 | 0.7975 | 0.7993 | 0.5790 |
| `alpha_final` 均值 | 0.01035 | 0.01405 | 0.00127 |
| `delta_ctf` RMS 均值 | 573.85 | 68.89 | 246.68 |
| Final 相对 Base MAE变化 | -9.92% | -5.49% | -9.56% |

可见：

- mid/fine gate 经常接近其 0.8 上界；
- final gate 却非常小；
- raw `delta_ctf` 的幅值非常大；
- 最终有效 correction 依靠“小 gate × 大 delta”得到。

当前损失包含：

```text
lambda_v14_gate × mean(alpha_final)
```

但没有直接约束 raw `delta_ctf` 的尺度。对于相同的有效 correction：

```text
alpha × delta
=
(alpha / k) × (k × delta)
```

减小 `alpha`、增大 `delta` 可以保持输出近似不变，同时减小 gate penalty。因此当前损失存在明确的尺度补偿方向。

这意味着 `alpha_final` 不能直接解释为可靠的安全概率，也可能导致：

- 优化条件数变差；
- gate 更容易饱和或塌缩；
- 不同数据集间 correction 尺度不可比较；
- 小幅改变 correction 强度时结果剧烈波动。

### 2.3 V19 给出的进一步证据

V19 只对 V14 的有效 residual 增加 `[0.5,1.5]` 通道增益，但正式实验中：

- TaxiBJ `gamma` 均值约 1.49985；
- BikeNYC `gamma` 均值约 1.48102；
- CHAP `gamma` 均值约 1.48941；
- V19 相对同权重 V14 anchor 在 22/24 点改善；
- 但 V19 相对独立 V14 的 RMSE仅在 6/24 点改善。

因此可以提出两个相互关联的判断：

1. V14 的有效 residual 在很多训练轨迹中偏弱；
2. 无条件放大 residual 会改善多数普通误差，却可能放大少量大误差。

下一步应同时解决：

```text
correction 强度校准
+
大误差尾部安全
```

而不是只继续放大 residual。

### 2.4 多尺度和专家路由仍存在可疑点

V14 八点平均诊断显示：

| 数据集 | Fine scale gate | Mid scale gate | Coarse scale gate |
|---|---:|---:|---:|
| TaxiBJ | 0.9020 | 0.0980 | 0 |
| BikeNYC | 0.7016 | 0.1471 | 0.1513 |
| CHAP | 0.7000 | 0.2302 | 0.0698 |

TaxiBJ 配置本身只启用 fine+mid，因此 coarse 为 0 是预期行为；但 mid 权重仍偏低。BikeNYC 和 CHAP 虽启用 coarse，最终 scale gate 仍明显偏向 fine。

专家熵在部分点接近 0，说明某些尺度的专家选择高度集中。但路由塌缩是否真正造成误差，目前只有相关现象，没有因果证据。

因此，多尺度和路由应排在 correction 校准之后探索。

## 3. 必须先统一的实验基础

### 3.1 建立干净的探索分支

建议从当前 V14 创建：

```bash
git switch v14-single
git switch -c v14-exploration
```

先提交所有“只增加诊断、不改变模型输出”的代码，再开始实验。每次正式运行必须满足：

```text
git_dirty = False
```

不要继续使用 dirty tree 生成论文正式结果。

### 3.2 统一指标口径

历史 V14 使用 batch 指标平均，V19 使用全数据集缺失元素精确累加。探索实验必须统一使用：

```text
global MAE
global RMSE
global MAPE/WAPE
```

其中：

- MAE、RMSE 使用 float64 累加；
- TaxiBJ/BikeNYC 不使用原始 MAPE 作为主结论；
- 增加 WAPE 或忽略近零目标后的 MAPE；
- 所有候选和重新运行的 V14 使用完全相同的指标实现。

### 3.3 固定公平比较条件

必须固定：

- 相同 train/val/test 划分；
- 相同 offline mask CSV；
- 相同模型种子；
- 相同 batch size；
- 相同 epoch 和 val interval；
- 相同 optimizer、scheduler、AMP 和梯度裁剪；
- 相同 checkpoint 选择规则；
- 相同测试脚本。

改变模型种子时，先保持 mask 不变，用于测量优化随机性。改变 random mask seed 的实验应单独进行，不能与模型种子实验混合解释。

## 4. 第一步：无训练诊断实验

这一步直接读取现有 V14 best checkpoint，不重新训练模型。预计数小时内即可完成 24 点诊断。

### 4.1 输出级 residual 倍率扫描

对每个 V14 checkpoint 定义：

```text
r_v14 = x_v14 - x_base
x(kappa) = x_base + kappa × r_v14
```

扫描：

```text
kappa ∈ {0, 0.5, 0.75, 1.0, 1.25, 1.5, 2.0}
```

执行规则：

1. 在验证集上计算各 `kappa` 的 MAE、RMSE；
2. 只根据验证集选择 `kappa`；
3. 使用选中的 `kappa` 在测试集运行一次；
4. 测试集 oracle 最优 `kappa` 只能作为诊断，不能当作正式结果。

需要输出：

```text
kappa_sweep.csv
kappa_val_curves.json
kappa_test_selected.json
```

重点回答：

- V14 residual 是否普遍偏弱；
- MAE 最优 `kappa` 与 RMSE 最优 `kappa` 是否冲突；
- 不同数据集和缺失模式的最优倍率是否一致；
- V19 的 1.5 上界是否过低、合理或过高。

### 4.2 通道级 residual 扫描

TaxiBJ 和 BikeNYC 为双通道，可在验证集扫描：

```text
kappa_channel ∈
{0.75, 1.0, 1.25, 1.5} × {0.75, 1.0, 1.25, 1.5}
```

共 16 个组合，不需要训练。

判断标准：

- 如果两个通道的最优 `kappa` 长期不同，通道 gate 假设成立；
- 如果两个通道总是选择相同上界，V19 的“通道自适应”假设不成立，问题只是整体 residual 尺度；
- 如果不同样本的最优倍率差异大，但通道均值接近，则应优先做样本难度校准，而不是通道校准。

### 4.3 每阶段预测误差

对以下输出统一计算隐藏位置 MAE/RMSE：

```text
x_base
x_coarse 上采样
x_mid 上采样
x_ctf
x_v14
```

同时计算边际变化：

```text
coarse → mid
mid → ctf
base → v14
```

目标是确认：

- coarse/mid/fine 哪一阶段真正提供有效信息；
- BikeNYC 的小 coarse 网格是否持续有害；
- CHAP 的 coarse 分支是否只增加 raw delta 幅度；
- TaxiBJ 的 mid 分支是否值得保留较高计算量。

### 4.4 Gate 与 residual 分布

不能只保存均值，需要保存：

```text
p05 / p25 / p50 / p75 / p95
min / max
saturation ratio
```

对象包括：

```text
alpha_mid
alpha_fine
alpha_final
delta_mid RMS
delta_fine RMS
delta_ctf RMS
effective_residual RMS = RMS(alpha_final × delta_ctf)
effective_residual / observed_scale
```

建议饱和定义：

```text
alpha_mid > 0.95 × alpha_mid_max
alpha_fine > 0.95 × alpha_fine_max
alpha_final < 0.05 × alpha_final_max
```

### 4.5 分层误差诊断

将隐藏目标按以下方式分桶：

1. 通道；
2. `target=0` 与 `target>0`；
3. `|target|` 的 0～50%、50～90%、90～99%、99～100% 分位；
4. 观测邻域密度低/中/高；
5. 时间缺口长度；
6. fixed/random；
7. 缺失率。

每个桶计算：

```text
count
MAE
RMSE
Base → V14 gain
大误差 Top-1% 占总平方误差比例
```

这一步用于解释为什么 V19 可以降低 MAE却提高 RMSE。

### 4.6 路由和尺度诊断

记录：

- 每个尺度各专家使用率；
- 归一化专家熵 `entropy/log(num_experts)`；
- 死专家比例；
- scale gate 分布；
- scale gate 与样本误差的相关性；
- 路由熵与 Base→V14 收益的相关性。

只有当“低路由熵与高误差”在多个数据集和种子上稳定相关时，才进入路由结构实验。

## 5. 代表性筛选点

完整候选不应一开始就跑 24 点。建议先使用 6 个核心点：

| 数据集 | 点 | 选择原因 |
|---|---|---|
| TaxiBJ | fixed@0.4 | V14 原本较强，V19 大幅退化，检验改动是否破坏稳定点 |
| TaxiBJ | random@0.4 | V14/V19 均存在训练波动，检验过拟合和尾部安全 |

| BikeNYC | random@0.8 | 高缺失率且 V19 有改善，检验残差增强价值 |
| CHAP | fixed@0.2 | V19 MAE/RMSE均退化，检验低缺失率安全性 |
| CHAP | random@0.4 | V19 MAE改善点，检验单通道收益 |

| 数据集 | 点 | 选择原因 |
|---|---|---|
| TaxiBJ | fixed@0.2 | V19 大幅改善，与 fixed@0.4 形成相反结果 |
| TaxiBJ | random@0.8 | V19 大幅改善，与 random@0.4 形成相反结果 |

6 个核心点按 V14 正式训练时长估算，每个候选约需：

```text
TaxiBJ 2 点：约 2.7 小时
BikeNYC 2 点：约 0.2 小时
CHAP 2 点：约 1.7 小时
合计：约 4.6 GPU 小时
```

## 6. 第二步：根因消融实验

这一轮只改变损失或标量配置，不先增加新结构。

### E00：重新运行统一口径 V14

目的：

- 建立新指标实现下的真实基线；
- 验证 clean Git、日志和 checkpoint；
- 后续所有候选与 E00 配对比较。

### E01：移除 final gate penalty

修改：

```text
lambda_v14_gate: 0.0001 → 0
```

其他结构、损失和训练参数不变。

假设：

- 当前 gate penalty 促进了“小 alpha、大 delta”的尺度补偿；
- 移除后 alpha/delta 的分解可能更自然；
- 有效 residual 和最终性能不一定恶化。

必须观察：

```text
alpha_final 分布
delta_ctf RMS
effective_residual RMS
MAE/RMSE
```

### E02：移除 gate penalty，并增加 raw delta 尺度约束

先定义每样本、每通道观测尺度：

```text
s_obs = mean(|x_obs| | observed) + eps
```

建议诊断形式：

```text
L_delta_scale =
mean(log1p(RMS(delta_ctf) / s_obs)^2)
```

候选权重：

```text
lambda_delta_scale ∈ {1e-5, 1e-4, 1e-3}
```

先在 2 个点上做权重预筛：

```text
TaxiBJ fixed@0.4
CHAP random@0.4
```

再把最稳定权重运行到 6 个核心点。

目的：

- 直接打破 alpha/delta 的尺度不可辨识；
- 避免 raw correction 无限增大；
- 不直接限制最终有效 residual 的方向。

### E03：增加 RMSE 非退化约束

按样本计算缺失位置 RMSE：

```text
rmse_final = RMSE_sample(x_v14, target)
rmse_base  = RMSE_sample(stopgrad(x_base), target)

L_rmse_regret =
mean(ReLU(rmse_final - rmse_base))
```

候选权重：

```text
lambda_rmse_regret ∈ {0.01, 0.03, 0.05}
```

目的：

- 保留 MAE主目标；
- 抑制少量大误差；
- 针对 V19 中“MAE改善、RMSE退化”的直接问题。

### E04：替换元素级 regret 为样本级双指标 regret

当前 V14 regret 更接近元素级绝对误差非退化。可比较：

```text
L_sample_mae_regret
+
lambda_rmse_regret × L_sample_rmse_regret
```

E04 必须在 E03 证明 RMSE regret 有效后再运行，避免同时改变太多因素。

### E05：固定 residual 倍率

如果无训练 `kappa` 扫描表明多个点的验证最优倍率集中在相同范围，可测试：

```text
x_final = x_base + kappa_fixed × alpha_final × delta_ctf
```

候选：

```text
kappa_fixed ∈ {1.15, 1.25, 1.5}
```

该实验用于判断：

- 是否根本不需要新增控制器；
- 一个固定倍率能否复现 V19 的内部收益；
- 训练时是否会被原网络参数重新吸收。

如果训练后 alpha/delta 自动反向补偿，说明必须先解决尺度不可辨识，而不是继续增加乘法 gate。

## 7. 第三步：最小结构候选

只有完成无训练诊断和根因消融后，才进入结构实验。

### S01：可辨识的有效 residual 参数化

目标不是重新设计 residual pyramid，而是直接输出可解释的有效修正：

```text
r_direction = normalize(delta_ctf)
r_magnitude = bounded_controller(observed_features)
r_effective = r_magnitude × r_direction
x_final = x_base + r_effective
```

必须满足：

- 不复制 Backbone；
- 不新增第二套多尺度网络；
- 初始化时 `r_effective=0`；
- magnitude 使用观测尺度归一化；
- 方向和幅度不可通过任意缩放互相补偿。

该候选只有在 E01/E02 证明尺度不可辨识确实影响性能后才值得实现。

### S02：保守通道级 final gate

只有当通道 `kappa` 扫描显示两个通道的最优倍率稳定不同时，才增加通道粒度。

建议直接把 V14 final gate 从：

```text
[B,1,1,1,1]
```

扩展为：

```text
[B,C,1,1,1]
```

而不是在 V14 输出后再叠加第二个增益控制器。

约束：

- 共享 MLP；
- 通道统计只来自观测位置；
- 初始行为严格等于 V14；
- 增益范围先使用 `[0.8,1.2]`；
- 记录每个通道独立 gamma，而不是只记录整体均值；
- 增加饱和比例监控。

### S03：尾部感知安全 gate

如果分层误差显示大误差集中在特定样本难度或观测稀疏区域，可让 final gate额外接收：

```text
observed target-free scale
base observed error
ctf observed error
observed residual q95
neighbor density
temporal gap score
```

输出仍是单个 V14 correction，不增加新方向或新 residual。

### S04：自适应尺度修正

只有阶段预测诊断证明 coarse/mid/fine 的收益在数据集或样本间明显不同，才测试：

```text
r_effective =
g_coarse × r_coarse
+ g_mid × r_mid
+ g_fine × r_fine
```

要求：

- gate 之和归一化；
- 可关闭有害尺度；
- 不复制专家；
- 每个尺度 residual 均需记录独立 MAE增益；
- 不允许同时引入通道 gate。

### S05：路由熵修复

只有在路由熵与误差存在稳定相关时才测试：

- router temperature；
- entropy floor；
- 更强 load balance；
- dead expert penalty。

不要在 correction、tail loss 和 routing 上同时改动。

## 8. 候选筛选规则

### 8.1 六点单种子筛选

每个候选必须在完全训练后满足：

| 指标 | 进入下一轮的最低要求 |
|---|---|
| 6 点平均相对 MAE | 改善至少 0.5% |
| MAE胜点 | 至少 4/6 |
| 6 点平均 RMSE | 不得退化超过 0.5% |
| 单点 MAE最大退化 | 不超过 2% |
| 单点 RMSE最大退化 | 不超过 3% |
| NaN/Inf | 0 |
| 参数增量 | 不超过 V14 的 1% |
| 训练时间增量 | 不超过 5% |
| gate/residual | 不得出现无解释的全面边界饱和 |

如果候选只改善 MAE但明显恶化 RMSE，不进入正式版本。

### 8.2 实际显著性阈值

单种子相对变化建议划分为：

```text
改善超过 0.5%：明确改善
变化在 ±0.5%：基本持平
退化超过 0.5%：明确退化
```

不要把 0.05%～0.1% 的变化解释为结构提升。

## 9. 第四步：多随机种子验证

对筛选出的最多两个候选，在 6 个核心点运行：

```text
seed ∈ {42, 2026, 3407}
```

### 9.1 优化随机性实验

保持 offline mask CSV 完全相同，只改变：

- PyTorch seed；
- NumPy seed；
- DataLoader shuffle seed；
- 参数初始化。

这样测量的是模型优化稳定性。

### 9.2 Mask 随机性实验

只对 random 模式的关键点额外生成：

```text
mask_seed ∈ {42, 2026, 3407}
```

模型种子固定为 42。这样测量的是随机缺失实例敏感性。

两种随机性必须分别汇总。

### 9.3 多种子通过标准

候选需要满足：

- 6 个点中至少 4 个点的三种子平均 MAE优于 V14；
- 三数据集不能有一个整体退化超过 0.5%；
- RMSE平均不退化；
- 任一 seed 不出现超过 3% 的严重退化；
- 相对改善的 95% bootstrap CI 尽量不跨过 0；
- 参数量、显存和训练时间满足预算。

## 10. 第五步：全量 24 点正式验证

## 13. 计算预算

按 V14 当前日志估算：

| 内容 | 估计 GPU 时间 |
|---|---:|
| 24 checkpoint 无训练诊断 | 小于 2 小时 |
| E00 core6 | 约 4.6 小时 |
| 4 个单变量候选 core6 | 约 18.4 小时 |
| Top-2 补两个模型种子 | 约 18.4 小时 |
| Top-1 剩余 18 个正式点 | 约 13.8 小时 |
| 汇总与复核 | 小于 1 小时 |
| 推荐方案合计 | 约 55～60 GPU 小时 |

如果增加更多结构候选或 random mask seed，完整严谨探索约需 80～120 GPU 小时。

服务器稳定性优先，建议：

- 单 GPU 顺序运行；
- 不同时在两张卡上运行高功耗任务；
- 每个任务设置合理 CPU threads；
- 每组完成后释放模型和 CUDA cache；
- 记录显存、功耗和温度；
- 支持断点跳过已完成组合。

## 14. 最重要的决策树

```text
V14 residual kappa 扫描
        |
        +-- 大多数点最优 kappa > 1
        |       |
        |       +-- 两通道最优值相同
        |       |       -> 优先 correction 尺度/损失，不做通道 gate
        |       |
        |       +-- 两通道最优值稳定不同
        |               -> 测试 S02 通道级 final gate
        |
        +-- MAE最优 kappa 与 RMSE最优 kappa 冲突
        |       -> 优先 E03 RMSE regret / S03 tail-safe gate
        |
        +-- 最优 kappa 随样本难度明显变化
        |       -> 测试 difficulty-conditioned final gate
        |
        +-- coarse/mid 阶段经常有害
        |       -> 测试 S04 自适应尺度关闭
        |
        +-- 路由低熵与高误差稳定相关
                -> 最后测试 S05 路由熵修复
```

## 15. 最终建议

当前最高优先级不是继续增加 MoE 专家或新增复杂分支，而是：

1. 用无训练 `kappa` 扫描确认 V14 有效 residual 的合理强度；
2. 验证 `lambda_v14_gate` 是否导致 alpha/delta 尺度补偿；
3. 用 RMSE regret 解决 MAE改善但尾部误差恶化；
4. 只有证据支持时才增加通道 gate 或自适应尺度；
5. 所有候选坚持单变量、完整训练、多点筛选和多种子验证。

最值得先运行的实验是：

```text
D01 residual kappa 扫描
→ E01 移除 gate penalty
→ E03 RMSE regret
→ E02 delta 尺度约束
→ 有效单项组合 E04
```

这条路线直接针对 V14 当前最明确的结构问题，新增复杂度最低，也最容易解释某项改动为什么有效或为什么失败。
