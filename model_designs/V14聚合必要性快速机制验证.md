# V14 分支：聚合必要性的快速机制验证

## 定位

回答“只有细粒度观测时，为什么还需要构造粗尺度”，而非再次优化完整 V14 的排名。
当前 V14 的主干、粗到细修正、条件编码和辅助损失存在多条粗尺度路径，
简单关闭一个配置项不能构成干净的 Fine-only 对照。

因此新增独立的小型机制探针，**复用当前 V14 的 ResidualSTBlock，不修改或冒充完整 V14**。
结果只能支持该探针及当前子样本预算下的假设，不能直接与历史 V14 完整训练的 MAE 比优劣。
本脚本不依赖 V22 文件，也不移植此前 V22 完整模型。

## 第一阶段：base，默认 30 组

三个数据集 × 两种掩码几何 × 五个模型，seed=42。

| 名称 | 上下文构造 | 检验的问题 |
|---|---|---|
| fine_local | 所有分支保持细网格、普通时空卷积 | 纯细尺度参照 |
| fine_wide | 仍保持细网格，仅增加空间卷积 dilation | 收益是否只是看得更远 |
| fixed | 观测感知的固定块聚合，stride 2/4 | 构造粗尺度有没有增益 |
| geometry | 相邻锚点、固定距离权重软聚合 | 不学习成员关系的宽邻域参照 |
| adaptive | 与 geometry 同候选锚点，内容相似性学习软分配 | 学习“谁和谁聚合”有没有增益 |

fine_local/fine_wide/fixed/geometry 的有效可训练参数数量完全相同；
两条 context block 在 Fine-only 中真正参与计算，不靠挂载闲置参数凑容量。
共享模块在相同种子下具有相同初始权重。
adaptive 多出少量 query/key 参数；结果明确输出有效参数数量，不宣称严格参数相等。
扩大 dilation 是更大感受野控制，不是与所有聚合路径严格相同的有效感受野或 FLOPs 控制。

## 第二阶段：moe，可选

同样六个数据集/掩码点，对比 adaptive / uniform / moe。
若 base 已完整运行，则 adaptive 六组自动复用，仅新增十二组：

- uniform：固定、局部学习、较宽学习三个粗化视图等权组合分配。
- moe：三个粗化视图通过学习的路由权重组合分配。

先组合 Fine→Coarse 分配，再聚合观测特征，经共享类型的粗尺度处理后按同一分配回投。
专家没有独立预测头。局部与较宽分配共用每尺度 query/key，控制额外容量。
这仍是轻量软粗化探针，粗节点使用锚点网格的 V14 残差块，不是完整的不规则区域图补全模型。

`--stage all` 运行七个模型，共 42 组；不要一开始就扩大到全缺失率。

## 数据与掩码：专门控制缺失几何

从现有 NPZ 原始 train/val/test 划分分别均匀抽取窗口：128 / 32 / 32。
保持完整的通道、时间和空间尺寸；实际索引写入每组 config.json。
不混用原始测试集训练，不读取外部 Mid/Coarse 或隐藏目标构建区域。
NPZ 通过流式读取控制内存；压缩文件仍需解压到选定索引，读取时间不是零。
原始划分如有跨窗口重叠，本脚本不额外改变或声称消除它。

两种新掩码，**不是历史 fixed/random CSV**：

- scattered：空间随机选择缺失格点。
- block：在随机中心附近形成紧凑缺失区域。

两种掩码都在窗口内沿时间固定，且都恰好遮掉 `round(0.4*H*W)` 个空间格点，
因此时间持续性与缺失数量一致，只主要改变空间聚集形态。
边界裁剪及精确数量要求可能使 block 不完全是矩形。
掩码仅依赖 seed、split 和原窗口索引，不依赖数值；同场景下所有模型得到完全相同的掩码和样本顺序。
不同 split 使用不同随机种子。不会覆盖用户 CSV。

这检验“分别在两种几何下训练时是否有差异”；**不是**只在散点训练、在块状测试的分布外泛化实验。
默认仅一个缺失率和种子，不能推论所有缺失率/所有数据集情形。

## 训练与评估

所有组采用同一个协议：

- dim=16；原始 V14 时空残差块，无 dropout；每尺度相同类型的处理模块。
- 20 epoch，batch=8，每 2 epoch 验证，最后一轮必验证。
- AdamW，lr=0.001，weight_decay=0.0001，余弦衰减，梯度裁剪 1。
- 观测位置的逐样本逐通道标准化，标准差下限为 1。
- 只对缺失位置计算标准化 Smooth L1；不加不同版本的粗尺度辅助损失。
- 只按验证 MAE 保存一个 best.pt，改进时原子覆盖。
- 最后加载最佳参数，再测试一次；原始数值范围按全部缺失元素累计 MAE/RMSE。
- 单卡串行；不会使用 DDP、修改 GPU 功率或自动操作其他训练进程。

输出路径：`outputs/v14-exploration/aggregation_probe/数据集/掩码/模型/指纹/时间/`。
包含 config.json（含样本索引）、best.pt、result.json、logs/train.log、val.log、test.log、metrics.jsonl。
配置/代码/数据身份发生变化会使用新指纹；旧目录保留。
缺少完整训练记录、最终 test 或 best.pt 的任务不会跳过；重新训练写入新时间目录，不冒充断点续训。

## 执行顺序

在项目内层目录，使用已安装 PyTorch 的 difftdi 环境：

```bash
conda activate difftdi

# 1. 先检查任务计划，不训练、不生成实验目录
python scripts/v14-exploration/run_aggregation_probe.py --gpu 0 --dry-run

# 2. 第一阶段：30 个小实验；默认跳过相同协议下已完整完成的任务
python scripts/v14-exploration/run_aggregation_probe.py --gpu 0

# 3. 控制台汇总，包括未完成项及验证集相对变化
python scripts/v14-exploration/run_aggregation_probe.py --gpu 0 --summary

# 4. 仅当第一阶段值得继续时，再验证多专家与路由
python scripts/v14-exploration/run_aggregation_probe.py --gpu 0 --stage moe

# 5. 查看两阶段合并结果（未运行的组会标 MISSING）
python scripts/v14-exploration/run_aggregation_probe.py --gpu 0 --stage all --summary
```

仅做一个任务的 1 epoch 流程检查：

```bash
python scripts/v14-exploration/run_aggregation_probe.py --gpu 0 --epochs 1 --max-jobs 1
```

1 epoch 与 20 epoch 指纹不同，不会误跳过正式筛选。`--max-jobs` 限制本次新增执行的任务数。
`--cpu` 可检查 CPU 流程，CPU/GPU 结果指纹隔离。
`--datasets BikeNYC` 可先跑十组更小的数据集实验，但单数据集结果不能替代跨数据集验证。
修改训练预算、样本上限、种子或模型宽度时改 `configs/v14-exploration/aggregation_probe.json`。

## 如何判断结果

优先看同数据集、同掩码、同种子的**验证集配对变化**，而不是挑测试集冠军。

1. fixed 比 fine_local 好，但不比 fine_wide 好：暂不支持粗尺度有独立必要性；可能只是感受野作用。
2. fixed 同时优于两个 Fine 控制：支持当前小模型下构造区域上下文有价值，但仍需充分训练和多个种子复核。
3. adaptive 只优于 fixed，不优于 geometry：可能主要受益于软化/扩大邻域，尚不能归因于学习分配。
4. adaptive 同时优于 fixed 和 geometry：学习区域构造有更强支持，尤其关注是否在块状缺失下更明显。
5. uniform 优于 adaptive：多个聚合偏好可能有价值，但不是 MoE 路由有效的证据。
6. moe 不优于 uniform：不支持学习式路由有必要，不要为保留 MoE 而选择性报告。

同时查看 RMSE、不同数据集一致性和最佳轮次。若最佳 epoch 普遍贴近 20，说明短预算可能影响排名。
小幅差异（如不足 1%）先视作待复核信号，不称为显著提升。
脚本输出跨场景的相对变化均值，不直接平均 TaxiBJ/BikeNYC/CHAP 的原始量纲 MAE。

本实验不能证明：真实区域的物理边界、粗节点是独立观测、方法原创性、完整 V14 已提升、论文最终效果。
也不能凭一轮结果否定所有多尺度方法。负结果首先应结合优化程度、子样本量与构造方式解释。
