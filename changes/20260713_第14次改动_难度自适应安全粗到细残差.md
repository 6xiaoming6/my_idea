## 2. 修改目标

保留 main 的稳定预测作为 `x_base`，复用 main 已经计算出的 `z_f/z_m/z_c/h_main`，增加一个可关闭的粗到细候选分支，并通过样本级安全门控制最终残差：

```text
x_base = MainBackbone(x_obs, mask)
x_ctf = SafeCoarseToFineRefiner(z_f, z_m, z_c, h_main)
delta_ctf = CorrectionAdapter(x_ctf - x_base, x_base, x_ctf)
x_final = x_base + alpha_final * delta_ctf
```

安全初始化满足：

```text
alpha_mid  ≈ 0.038
alpha_fine ≈ 0.038
alpha_final ≈ 0.0033
CorrectionAdapter 最后一层 = 0
初始化 x_final 严格等于 x_base
```

## 3. 新增模型模块

### 3.1 `DifficultyConditionEncoder`

新增文件：`src/stmoe_imputer/models/v_single/difficulty_condition.py`。

在 fine/mid/coarse 三个尺度分别计算 9 个仅依赖观测值和 mask 的统计量，共 27 维：

```text
missing_rate
observed_ratio
temporal_gap_score
spatial_block_score
neighbor_density
local_value_variance
temporal_variance
scale_reliability
cross_scale_consistency
```

局部/时间方差在进入 MLP 前执行 `log1p`，避免原始流量尺度过大。完整原始统计仍保留用于诊断。跨尺度参考只从已观测的多尺度输入构造，不读取 `x_f_gt`。

### 3.2 `SafeCoarseToFineRefiner`

新增文件：`src/stmoe_imputer/models/v_single/safe_c2f_refiner.py`。

结构为：

```text
z_c -> coarse_head -> x_coarse
x_coarse↑ + alpha_mid * MidResidual(z_m, embed(x_coarse↑)) -> x_mid
x_mid↑ + alpha_fine * FineResidual(z_f, h_main, embed(x_mid↑)) -> x_ctf
concat(x_ctf-x_base, x_base, x_ctf) -> CorrectionAdapter -> delta_ctf
```

Fine head 默认额外使用 main 的融合特征 `h_main`，用于保护 BikeNYC 等小型非方形网格上的细粒度信息。CorrectionAdapter 最后一层零初始化，保证初始输出不破坏 main。

### 3.3 `ObservedConsistencyEvaluator` 与 `SafetyController`

新增文件：`src/stmoe_imputer/models/v_single/safety_controller.py`。

控制器第一阶段根据以下前置条件产生 `alpha_mid/alpha_fine`：

```text
Difficulty embedding: 32
Mid/Coarse reliability: 2
main scale gate: 3
grid geometry: 5
```

生成 `x_ctf` 后，再在真实观测位置计算 5 个可测量统计量：

```text
base observed MAE
ctf observed MAE
ctf-base observed MAE difference
|ctf-base| observed mean
|ctf-base| observed q95
```

最终控制器结合前置条件和观测一致性输出 `alpha_final`。一致性计算中的候选预测被 detach，防止候选分支通过“操纵安全信号”而非改善预测来提高 gate。

### 3.4 `V14SafeC2FMoE`

新增文件：`src/stmoe_imputer/models/v_single/v14_safe_c2f_moe.py`。

该类包装且只调用一次 main Backbone，输出保留原训练器 contract，并新增：

```text
x_hat_base
x_hat_ctf
x_hat_mid
x_hat_coarse
diagnostics.v14
```

`reuse_main_features=false` 会明确报错，避免误配置后悄悄复制第二套 Encoder/MoE。

## 4. Architecture Registry 与 main 兼容性

新增 `src/stmoe_imputer/models/registry.py`：

```text
main -> MultiScaleMoEBackbone
v14_safe_c2f_moe -> V14SafeC2FMoE
```

`DualBranchSTImputer.from_config` 改为通过 registry 构造模型。配置未指定 `model.architecture` 时仍默认选择 `main`，因此原有 main 配置和结果目录不变。

## 5. Loss 修改

在保留 main 原有主损失、跨尺度损失、MoE balance、shared/route auxiliary 和 complementary loss 的基础上，仅当输出包含 `x_hat_base` 时增加：

```text
L_v14_base   = SmoothL1(x_base, y_hidden)
L_v14_mid    = SmoothL1(x_mid, y_mid_hidden)
L_v14_coarse = SmoothL1(x_coarse, y_coarse_hidden)
L_regret     = mean(ReLU(|x_final-y| - |stopgrad(x_base)-y|))
L_gate       = mean(alpha_final)
```

默认权重：

```text
lambda_base   = 0.25
lambda_mid    = 0.05
lambda_coarse = 0.03
lambda_regret = 0.10
lambda_gate   = 0.0001
```

同时记录 base/ctf/final hidden MAE 和非退化违反比例。所有监督目标只在 Loss 中读取，模型 Forward 不读取 ground truth。

## 6. 优化器、日志与可复现性

- 新增 `train.lr_v14`，V14 新模块使用独立 AdamW 参数组。
- V14 bias 和 normalization 参数不做 weight decay。
- 诊断范数统一先转换到 FP32 再平方，避免 AMP 下溢出为 Inf。
- 每个 epoch 记录 alpha 的 mean/std/min/max、难度、可靠性、几何、观测一致性、残差范数、专家熵和专家使用率。
- 训练日志新增完整 Git commit、branch、dirty 状态、配置 SHA-256、Torch/CUDA/GPU 信息。
- 修复 `conda run` 环境找不到 Anaconda 根目录 Git 时日志错误写为 unavailable 的问题。

## 10. 合理调整说明

设计文档推荐开发阶段进行 warm-start 三阶段训练。当前第一版实现保留 `freeze_main` 和独立 `lr_v14` 能力，但正式默认采用与 main 相同协议的 from-scratch 联合训练，避免论文对比引入预训练优势。自动加载 main checkpoint、按阶段改变冻结范围和重建 optimizer 暂未默认启用，后续应作为独立训练协议实现与报告。

设计文档把单个 Controller 伪代码写成一次输出三个 logit；实际实现拆成 refinement gate 和 final gate 两个共享目标但独立的小网络，因为 `alpha_final` 必须在 `x_ctf` 生成、观测一致性可计算之后才能得到。这符合文档推荐的两阶段单次稳定 Forward。
