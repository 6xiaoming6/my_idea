# LT01–LT10：独立 latent token 空间

用户已澄清：latent不应是F/M/C任何大小的网格。因此先前的L01–L10网格队列已暂停，L01保存到80epoch，其他组未启动。此前产物保留，只作为被澄清替代的实现记录，不计入本轮十组，也不与本轮混合排序。

本轮基于固定0.5/0.5损失的I37，分支`latent-tokens`。不覆盖best正式版本。

## 数据流

```text
X_F → 原编码器 → 网格到token交叉注意力 ┐
X_M → 原编码器 → 网格到token交叉注意力 ├→ 融合 → Z0
X_C → 原编码器 → 网格到token交叉注意力 ┘

每轮：Zi-1 → 选尺度 → token差分/历史消息
      → 该尺度位置查询tokens → 原生尺度网格
      → 融合该尺度原始可见观测 → Top-2专家
      → token查询读取专家结果 → Zi

Z4 → F位置查询tokens → F隐藏特征 → Decoder
   → 可学习分配投影 → F_complete
```

公共latent形状为`[B,T,K,D]`，默认K=128、D=64，T保持12。token没有二维网格坐标，K可设为97等非平方数，不要求与H/W对应。内部沿用旧通道优先接口，以`[B,D,T,K,1]`存放同一批token；K轴不做空间卷积、池化或二维重排。每轮的空间专家仅在选中尺度的真实网格上运行。

保留时间轴，使每个时间步持有K个空间token；本批不研究把全部时空压成一条无时间结构的token序列。

双向映射使用单头交叉注意力，query/key为16维，value/output为64维，无dropout、无bias。网格写入token时，Q是可学习槽位，K来自网格特征加原生位置，V是网格特征。token恢复到网格时，Q是原生网格位置，K是token状态加槽位嵌入，V是token状态。只沿独立的batch×time维分块，不限制注意力的空间覆盖。

初始值/输出投影为恒等，token槽位为随机学习参数。不同K从相同256槽位初始库取前缀；其他保留参数初始化与I37逐项相同。新参数在独立随机数流中创建。

## 十组配置

| 编号 | 对照 | 改动 | 检验问题 |
| --- | --- | --- | --- |
| LT01 | I37 | 每时间步128个token，共享双向映射，直接写回 | 无网格表示的基本可行性 |
| LT02 | LT01 | 64个token | 更强信息压缩能否兼顾精度与成本 |
| LT03 | LT01 | 256个token | 增加容量是否改善细节恢复 |
| LT04 | LT01 | F/M/C各自一套双向映射，各轮共享 | 尺度适配是否需要独立参数 |
| LT05 | LT01 | 将原生尺度状态增量编码为token，再残差写回 | 避免完整覆盖token是否有益 |
| LT06 | LT01 | 去掉受控差分 | 统一槽位后的差分是否必要 |
| LT07 | LT01 | 去掉历史读写 | 历史是否有独立价值 |
| LT08 | LT06/LT07 | 同时去差分与历史 | 纯顺序token状态及通信冗余 |
| LT09 | LT01 | 固定CMFF，其他保持相同 | 自由尺度选择的作用 |
| LT10 | LT04/LT05 | 独立尺度映射＋残差写回 | 预先固定的组合探索 |

LT04/LT10的三个尺度映射初始从相同模板复制，因此LT04在初始化时与LT01前向相同，之后参数独立更新。LT05/LT10：下一轮token = 当前修正token + encode(专家输出 − decode(当前修正token))；零增量严格写回零。

历史仍存可见F回填后的P1/P2/P3，因果且detach。读取器产生F消息，再经F→token交叉注意力写入；额外限制消息RMS不超过隐藏token RMS的0.1。无bias映射保证零消息不会制造新信号。中间F读出只服务历史和诊断，跨轮状态始终在token空间。

差分计算同一组槽位相邻轮的变化，沿用RMS匹配和±0.1门控。路由隐藏摘要使用token均值与每时间步的全局缺失比例，不把F格点mask直接视作token mask。原I37路由读取时机及H0预测补位策略保持，不混入另一套输入时序改进。

## 协议、预检与筛选

TaxiBJ双通道12时间步；四类混合mask0.4、seed7；100epoch、batch32、每5epoch验证，AdamW，lr1e-3余弦降至3e-4，AMP，GPU1串行。共享八专家，每轮原生Top-2，共8次专家执行。除LT09外前三轮自由、末轮F。

损失：投影前/后F缺失L1各0.5；可见F0.1、投影前可见M/C一致性0.1、候选均衡0.01。只用可见F/M/C作输入和一致性约束，隐藏真值不进入路由、消息或历史。best只按ID验证MAE选择。

CPU验收包括：原I37回归、10组输出/梯度、8次专家执行、公共初始化及mask一致、97槽位与槽位置换、空/全观测及隐藏值污染、零消息、投影约束、完整CLI恢复与六套评估。GPU1用实际batch32检查全部配置的AMP、TA/ST与恢复；另检查256 token、FFFF路径、每轮TA/ST的高显存组合。

记录每轮token的RMS、槽位差异/RMS和平均槽位余弦相似度，用于发现槽位趋同。该诊断只能描述现象，不能自动证明导致精度变化的因果机制。

评估使用原六套协议，二元/形态先合并复测，再对三类OOD等权。先看ID不超过I37的103%，再比较OOD类别比值及最差类别。参数、显存和耗时一并披露；未达到门槛仍完整报告。单seed筛选不是统计显著性或独立确认。

冻结源码/配置/初始化/数据哈希。`scripts/queue_tokens.py --suite <目录>`串行运行LT01→LT10，完成跳过，中断从完整last恢复，失败停止。每run保存best/last、诊断、15秒GPU日志，自动正式报告完成后tmux退出。

固定数量latent token及交叉注意力本身是通用结构，不单独宣称原创。真实多尺度独立缺失、token空间跨轮通信和原生专家计算的组合是否有价值，需以本批ID/OOD及机制诊断判断。
