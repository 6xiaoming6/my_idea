## 通过的检查

1. **初始化一致**：seed7 全部状态哈希与冻结公共初始化一致：`2baf7361f1aa2308e5f2a55c07fd657e7d5feea87dd296ca071406aec3179f99`；参数量 347,930。
2. **真实 best 数值对齐**：分别运行冻结源码和发布源码，加载原 I37 epoch95 best，取相同 TaxiBJ 验证样本（2×12×32×32）。原始预测、投影后预测、回填结果、隐藏特征及损失逐元素完全一致；全部非空参数梯度的哈希一致。该样本损失为 7.2497076988220215。这是单样本 CPU 对齐检查，不是全测试集重评。
3. **模型契约**：每窗口恰好 8 次专家执行、末轮固定 F、可见 F 不变、可见 M/C 总量保持、污染隐藏值或标签不改变前向结果；损失和骨干梯度有限。
4. **训练恢复**：在小型合成多尺度数据上，连续两 epoch 与第一 epoch 停止后恢复的最终模型、优化器、调度器、scaler 及完整 RNG 状态哈希相等。完成后再次启动不改写检查点。
5. **完整命令行**：训练、恢复、六套评估、独立评估和无真值推理全部运行；单独评估与训练后评估的六套 MAE 一致；推理输出尺寸和可见值保留正确。
6. **数据准备**：保持既有三份 split 的 F 值，正确生成 2×2、4×4 区域总量，并拒绝覆盖目标数据。
7. **GPU1 实际尺寸验证**：RTX 3090，batch32×2×12×32×32，AMP 前向/反向及一次优化更新通过；共 256 次按样本计的专家执行（32×8），末轮均为 F；模型、优化器、scheduler、scaler 可恢复，RNG 恢复后相同。峰值 allocated 显存约 8.4835 GiB。此值是一次预检，不代表完整训练的最坏显存。轻量 GPU 监控写入独立预检目录。首次预检脚本误用了梯度裁剪字段名，在已通过前后向后退出；更正为原配置 `grad_clip_norm` 后重跑通过，未修改模型实现。
